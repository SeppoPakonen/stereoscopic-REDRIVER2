## Scope

The first feed slice of T5.2: rewire the **terrain / tile / road** plot path —
`DrawTILES` (tile.c) and `RenderModel` (draw.c) — to **submit world-space
`DrawCommand`s** into the draw-command arena (`drawcmd.h`) under
`-renderer dx11`, while keeping the legacy GTE + `addPrim` path byte-identical
for `-renderer psyx`.

This is the **feed (producer) half**: real terrain/tile geometry →
`DrawCommand` list. The **consumer half** (DrawGame's dx11 branch calling
`Dx11GameFeed_RenderFrame`, and later switching the GTE draw off in favour of
the renderer) is a separate step — see "Deferred".

## Design

### World-space convention (critical)

`DrawCommand.world` (a `MATRIX`) is **world space**: rotation + translation
(trans in `t[0..2]`). The renderer (`Dx11GameFeed_RenderFrame`) builds its own
per-eye stereo view from `camPos`/`yawRad` and applies `clip = model_vertex ·
world · view · proj`. So the feed must pass the **world** rotation and **world**
position — **not** the camera-space `CompoundMatrix[yang]` the game feeds the
GTE.

- **Tiles** (`DrawTILES`): world rotation = `matrixtable[yang]` (pure-Y MATRIX,
  t=0, `CalcObjectRotationMatrices`), world position = `ppco->pos`
  (`(vx, vy>>1, vz)` — the same scribble the game passes to
  `Apply_InvCameraMatrixAndSetMatrix`), camera depth `Z` from that call.
- **Models** (`RenderModel`): world rotation = the `matrix` param, world
  position = the `pos` param (already world space; `NULL` → identity / none).

### Helper — `PlotFeed_SubmitModel` (draw.c, declared in draw.h)

Builds + submits one `DrawCommand` for a selected LOD `MODEL`:

- `mesh` = the chosen LOD model.
- `world` = `worldRot` (or identity) with `t[0..2]` = `worldPos` (or 0).
- `material` = blend from `plotFlags` (`PLOT_TRANSPARENT` → translucent, else
  opaque), tpage/clut fallback read from the model's first poly (renderer
  resolves per-poly texture from the mesh anyway).
- `sortKey` = `z >> 1` (mirrors the OT `Z>>1` bucket).
- `flags` = `DRAWCMD_OPAQUE | DRAWCMD_TWOSIDED | DRAWCMD_FLAT` (+
  `DRAWCMD_TRANSLUCENT` when transparent).
- `palette`/`subdiv` = -1 (renderer tessellation/LOD is a follow-up).

### Integration points

1. `RenderGame2` (main.c): `DrawCmd_BeginFrame()` at the top under
   `Renderer_IsDX11()` — bounds the per-frame arena (the game is not wired to a
   consumer yet, so without this the arena would grow unboundedly).
2. `RenderModel` (draw.c): under `Renderer_IsDX11()`, submit a command
   (world = `matrix` + camera-depth of `pos`) before the GTE plot.
3. `DrawTILES` (tile.c): under `Renderer_IsDX11()`, submit a command per tile
   (world = `matrixtable[yang]` + `ppco->pos`, depth `Z`) after LOD selection.

### Non-breaking parallel submit

Under dx11 this slice **appends a command and keeps the GTE draw running** in
parallel. Rationale: `-renderer dx11` is the default; until DrawGame's dx11
branch actually consumes the feed via `Dx11GameFeed_RenderFrame`, dropping the
GTE draw would blank the terrain/tiles. The GTE→renderer swap is the deferred
integration step. The feed is genuinely populated each frame and ready for the
consumer.
