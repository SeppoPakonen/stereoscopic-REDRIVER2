## Goal

Build the DX11 backend's native input layer as a game-agnostic DirectInput8
module: `CoInitialize` + `DirectInput8Create`, keyboard / mouse / joystick
devices (`SetDataFormat`, `SetCooperativeLevel`, `Acquire`), a poll state, and a
DIK scancode → logical-key mapping (ported from the game's SDL default mapping)
— verified headless with a dedicated harness.

## Scope (adjusted with the owner)

The original T1.7 ("keyboard/mouse/gamepad work under `-renderer dx11`, SDL2 →
DirectInput8 mapping") requires the running game with a focused window and real
input, which cannot be verified headless in this environment. Per the owner's
decision (same as T1.6), T1.7 is scoped to the first verifiable slice: a
**game-agnostic DirectInput8 input module + headless harness**. Wiring the
module into the game's `Pads[]`/`ReadControllers` consumers and the in-game
`-renderer dx11` input loop move to a follow-up task (T1.8).

## Context

SDL2 input is embedded in `PsyX_main.cpp` (`PsyX_UpdateInput`,
`PsyX_Sys_DoPollEvent`, `PsyX_Pad_*`). The DX11 path is a native DirectX stack,
so its input must be DirectInput8. The module stays game-agnostic: it exposes a
raw input state (keyboard scan array, mouse relative + buttons, joystick
buttons + axes) and a DIK→logical-key map; the game shim (later) maps logical
keys to the game's `Pads[]`. mingw32 has `dinput.h` + `libdinput8.a` (link
`-ldinput8`).

### Default mapping this mirrors (from `PsyCross/src/PsyX_main.cpp`)

| PSX pad | SDL scan | DirectInput DIK |
|---------|----------|-----------------|
| square  | X        | DIK_X |
| circle  | V        | DIK_V |
| triangle| Z        | DIK_Z |
| cross   | C        | DIK_C |
| L1      | LSHIFT   | DIK_LSHIFT |
| L2      | LCTRL    | DIK_LCONTROL |
| L3      | LBRACKET | DIK_LBRACKET |
| R1      | RSHIFT   | DIK_RSHIFT |
| R2      | RCTRL    | DIK_RCONTROL |
| R3      | RBRACKET | DIK_RBRACKET |
| select  | SPACE    | DIK_SPACE |
| start   | RETURN   | DIK_RETURN |
| dpad up/down/left/right | UP/DOWN/LEFT/RIGHT | DIK_UP/DIK_DOWN/DIK_LEFT/DIK_RIGHT |

## Design

`spike/dx11_input.{h,c}`:

- `Dx11Input_Create(HWND hwnd, Dx11InputResult*)` — `CoInitializeEx`, then
  `DirectInput8Create(DIRECTINPUT_VERSION, IID_IDirectInput8)`. Creates and
  configures the keyboard (`c_dfDIKeyboard`), mouse (`c_dfDIMouse`) and the first
  attached joystick/gamepad (`c_dfDIJoystick2`, axes enumerated + ranged) devices
  with `DISCL_NONEXCLUSIVE | DISCL_BACKGROUND` (no focus needed) and `Acquire`.
  Missing joystick is not an error (the gamepad is optional).
- `Dx11Input_Poll(inp, Dx11InputState*)` — `GetDeviceState` for each device; on
  `DIERR_INPUTLOST`/`DIERR_NOTACQUIRED` re-`Acquire` and zero that device's
  state. Fills `Dx11InputState { unsigned char keys[256]; int mouseX/Y/Z;
  unsigned char mouseButtons; unsigned char joyButtons[32]; int joyAxis[6]; int
  joyConnected; }`.
- `Dx11Input_MapKey(int dik)` — returns the `Dx11InputKey` (`DX11IK_SQUARE` …
  `DX11IK_RIGHT`, plus `ESC`/`BACKSPACE`/`ENTER`/`SPACE`/`F1`/`F2`/`F12`) for a
  DIK scancode, mirroring the table above.
- `Dx11Input_Destroy(inp)` — release devices, `di8`, `CoUninitialize`.

The harness (`spike/dx11_input_test.cpp`) creates a hidden Win32 window, creates
the input module, polls it, and asserts:
- `Dx11Input_Create` succeeds (`DX11INP_OK`).
- Poll returns a valid state (keyboard array readable, mouse/joystick fields
  populated; no crash under `DIERR_INPUTLOST` re-acquire).
- The DIK→logical map is faithful and collision-free: each of the 16 PSX pad
  actions (`SQUARE`…`RIGHT`) maps from exactly one DIK code, and the direct
  codes (`DIK_X`→`SQUARE`, `DIK_V`→`CIRCLE`, `DIK_Z`→`TRIANGLE`, `DIK_C`→`CROSS`,
  `DIK_UP`→`UP`, …) are correct.

## Verification

`premake5 gmake2 --cc=gcc` + `mingw32-make dx11_input config=release_x86`
(32-bit; mingw32 runtime DLLs beside the exe). Run
`bin/Release/dx11_input.exe`. Writes `dx11_input_result.txt` (init/poll/map
probes + PASS/FAIL).

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_input_result.txt:  INIT   create (result=0 expect 0) PASS
                       POLL   5 polls, state well-formed PASS
                       POLL   joystick device present (optional)
                       MAP    direct codes (16 checks) PASS
                       MAP    collision-free (16 distinct) PASS
                       UNMAP  unmapped DIK -> NONE PASS
                       TOTAL_FAILS=0 INPUT=PASS
```

The DirectInput8 module CoInitializeEx + DirectInput8Create, creates and
Acquires the keyboard/mouse/joystick devices (the attached gamepad was
enumerated successfully), polls into a well-formed `Dx11InputState` across
multiple polls (exercising the `DIERR_INPUTLOST` re-acquire path) without
crashing, and maps all 16 PSX pad actions from their DIK codes correctly and
collision-free (a stray DIK code returns `DX11IK_NONE`).

### Bugs found and fixed during verification

1. **mingw32 link: DirectInput GUIDs are in `dxguid`, not `dinput8`** — the
   first build failed to link with undefined references to `IID_IDirectInput8A`,
   `GUID_SysKeyboard`, `GUID_SysMouse` and the axis GUIDs (`GUID_XAxis` …).
   These live in `dxguid.a` (link `-ldxguid`), in addition to `-ldinput8`
   (DirectInput8Create) and `-lole32` (CoInitializeEx). Added `dxguid` to the
   premake links.
