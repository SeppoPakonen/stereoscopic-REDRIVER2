# T1.7 — DX11 platform & input (DirectX window + DirectInput8)

|            | |
|------------|-|
| **Phase**  | Phase 1 — Core DX11 renderer |
| **Milestone** | M1 — Core DX11 renderer |
| **Status** | planned |

## Goal

Provide the DX11 backend's native Windows platform + input layer: a Win32
message loop (window created in T1.1) and **DirectInput8** for keyboard, mouse
and gamepad, replacing the SDL2 input (`SDL_PollEvent`,
`SDL_GetKeyboardState`, `SDL_GameController*`, `SDL_SCANCODE_*` /
`SDL_CONTROLLER_*` mappings). SDL2 stays as the option for the GL backends.

## Context

SDL2 input is embedded in `PsyX_main.cpp` (`PsyX_UpdateInput`,
`PsyX_Sys_DoPollEvent`, `PsyX_Pad_*`, keyboard + controller mappings). The DX11
path is a native DirectX stack, so its input must be DirectInput8. A shared
input abstraction (SDL2 for GL, DirectInput8 for DX11) keeps the game's
`Pads[]`/`ReadControllers` consumers unchanged.

## Steps

- [ ] Define a shared platform/input interface (poll keyboard/mouse/gamepad,
      cursor, events) with an SDL2 implementation (existing, for GL) and a
      DirectInput8 implementation (new, for DX11).
- [ ] Implement the DirectInput8 backend: `IDirectInput8` init, keyboard
      (`IDirectInputDevice8` keyboard), mouse, and joystick/gamepad devices.
- [ ] Map DirectInput scancodes/buttons to the game's `Pads[]` / pad mapping
      (port the `SDL_SCANCODE_*` / `SDL_CONTROLLER_*` tables to DirectInput
      equivalents).
- [ ] Wire the Win32 message loop (WM_KEYDOWN/UP, WM_INPUT/mouse, WM_SIZE) for
      the `dx11` window; keep SDL event pumping for `psyx`.
- [ ] Replace `SDL_GetTicks` with Win32 `QueryPerformanceCounter` timing on the
      DX11 path where needed.
- [ ] Verify keyboard, mouse and a gamepad all work under `-renderer dx11`.

## Acceptance criteria

- [ ] Keyboard/mouse/gamepad input works under `-renderer dx11` via DirectInput8.
- [ ] The game's input consumers (`Pads[]`, pad mapping) are unchanged.
- [ ] `-renderer psyx` still uses SDL2 input, unaffected.
