## Goal

Implement split-screen: 2 players × 2 eyes = 4 images, user-selectable
horizontal/vertical split, composited in the DX11 renderer.

## Scope (adjusted with the owner)

The as-written T3.2 ("wire per-player camera + per-eye projection into each of 4
viewports from the game's `MPBuff[2][2]`") requires the running game. Per the
owner's decision (same as T1.6–T3.1), T3.2 is scoped to the verifiable slice:
extend the **game-agnostic `dx11_composite` module** with a **split-layout
composite pass** that maps 2 players × 2 eyes (4 eye SRVs) into four quadrants
of the backbuffer, for horizontal/vertical split × SBS/TB eye layout, and add a
headless harness that verifies the quadrant mapping. Wiring per-player cameras
into the game's DX11 render loop stays a later integration task.

## Context

The legacy split-screen gives each player half the screen (h or v), and each
player's view is itself SBS/TB when stereo is on. The renderer already supports
per-eye views (T2.2) and per-eye RTs (T2.1); tagging each eye's composite with a
screen quadrant turns the composite into a 4-viewport layout. The game's
`MPBuff[2][2]` double-buffers per player, so the per-player scene data is
available.

## Design

`spike/dx11_composite.{h,c}` (extended). New `Dx11Composite_SplitComposite`
pass that samples **four** eye SRVs (`p1Left/p1Right/p2Left/p2Right`):

- `Dx11CompositeSplit`: `DX11C_SPLIT_H` (players left/right halves),
  `DX11C_SPLIT_V` (players top/bottom halves).
- `Dx11CompositeEyeLayout`: `DX11C_EYE_SBS` (each player's eyes side-by-side
  within their half), `DX11C_EYE_TB` (each player's eyes top/bottom).
- `swap` flips which eye fills each player's left/top eye slot.
- The pass computes, per output pixel, the player region (from the split), the
  eye (from the eye layout within the region), rescales the UV into that
  quadrant, and samples the matching one of the four SRVs.

The harness (`spike/dx11_splitscreen_test.cpp`) creates four distinct solid-color
eye images (P1-LE=red, P1-RE=green, P2-LE=blue, P2-RE=yellow), composites each
(split × layout) into the backbuffer and probes all four background quadrants:
- `H_SBS` — left/right halves, each SBS → 4 quarter-columns map to the 4 eyes.
- `H_TB` — left/right halves, each TB → each player's eyes top/bottom.
- `V_SBS` — top/bottom halves, each SBS.
- `V_TB` — top/bottom halves, each TB.
- `SWAP` — swap flips the left/top eye within each player.

## Verification

`premake5 gmake2 --cc=gcc` + `mingw32-make dx11_splitscreen config=release_x86`
(32-bit; mingw32 runtime DLLs beside the exe). Run `bin/Release/dx11_splitscreen.exe`.
Writes `dx11_splitscreen_result.txt` (h/v × sbs/tb + swap probes).

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_splitscreen_result.txt:
   H_SBS P1L=(220,0,0) P1R=(0,200,0) P2L=(0,0,220) P2R=(220,200,0) PASS
   H_TB  P1L/P1R/P2L/P2R quadrant mapping PASS
   V_SBS P1L/P1R/P2L/P2R quadrant mapping PASS
   V_TB  P1L/P1R/P2L/P2R quadrant mapping PASS
   SWAP  P1 left=green P1 right=red (eyes swapped) PASS
   TOTAL_FAILS=0 SPLITSCREEN=PASS
```

The split composite maps the four eye images into the four quadrants exactly as
the legacy split-screen layout intends (horizontal/vertical player split ×
SBS/TB eye layout), with no cross-player or cross-eye contamination, and `swap`
flips the eye assignment within each player.

### Bugs found and fixed during verification

No bugs — the split-layout quadrant math (player region → eye → UV rescale)
was correct on the first build.
