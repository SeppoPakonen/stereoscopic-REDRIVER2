## Bugs found & fixed (making the companion window render)

Running the game was the first time the feed was exercised with **real** game
data (the headless harness used a synthetic near-scale scene), and it exposed
three in-game-only bugs:

### 1. Tile world positions were packed (cell-relative), not resolved

`DrawTILES` submitted the **raw** `ppco->pos` as the tile's world position. But
tile positions are stored **packed relative to the cell origin**
(`QuickUnpackCellObject`: `world = nearCell + (short)(ppco->pos - nearCell)`).
The raw values were ~260,000 units from the camera → everything beyond the far
plane → black.

Fix: `DrawMapPSX` now stores the **nearCell-resolved** world position of each
tile in a new `model_tile_pos[]` array (parallel to `model_tile_ptrs[]`), and
`DrawTILES`'s dx11 branch submits `model_tile_pos[tileIndex]` instead of the
raw `ppco->pos`. (Files: `draw.h`, `draw.c`, `tile.c`.)

### 2. Camera view direction was inverted vs the game's GTE

The game builds its view with `RotMatrixY(-(camera_angle.vy))`, so its GTE
forward is `+view z = (-sin,0,+cos)`. The DX11 yaw-derived forward is
`(sin,0,-cos)` — the opposite direction — so the camera looked away from the
terrain. Fix: `yawRad = camera_angle.vy * (2π/4096) + π` (a half-turn aligns the
two while keeping the DX11 right-handed `front = -z` convention the
projection expects). (`main.c` `Dx11Game_RenderFrame`.)

### 3. `MatWorldFromGte` stored the translation in the wrong matrix slot

The vertex shader is **row-vector** (`mul(pos, world)`), so the translation
must live in the **last row** (`world[3][0..2]`). `MatWorldFromGte` was storing
it in the **last column** (`world[i][3]`) — the column-vector convention. The
result: `mul(pos, world)` put the translation into the `w` component and the
geometry never moved to the tile position → it stayed at the model's local
origin, far from the camera → black. **The headless harness did not catch this**
because its world matrices had zero translation (identity), where both
conventions agree. Fix: `MatWorldFromGte` now writes the translation into the
last row. (`dx11_gamefeed.c`.)

### Renderer API addition

`Dx11GameFeed_RenderFrame` gained an optional `const float (*customView)[4]`
parameter (NULL = use the yaw-based `Dx11Stereo_ViewMatrix`, the prior
behaviour). The in-game consumer passes NULL; the game's own view matrix
(`inv_camera_matrix`) is available for a future pitch/roll-correct view.
Harness callers pass NULL. (`dx11_gamefeed.{h,c}`, `dx11_gamefeed_test.cpp`.)
