## Goal

Verify the DX11 renderer also renders the base (non-stereo) game correctly, so
the stereo work (T2.1–T3.3) does not regress normal play — and prove the DX11
**mono path** is self-contained and independent of any stereo configuration.

## Scope (adjusted with the owner)

The as-written T4.3 ("run representative missions under `-renderer dx11` with
stereo disabled and A/B against `-renderer psyx`") requires the running game,
which does not reach the gameplay loop headless in this environment (the full
`DrawGame` → draw-command → DX11 → per-eye → composite wiring is a later
integration task). Per the owner's established decision pattern (T1.6–T4.2),
T4.3 is scoped to the verifiable standalone slice: a **non-stereo regression
harness** that proves the DX11 **mono path** — the render path the game uses
when stereo is disabled (render the base view-projection directly to the
**backbuffer**, no per-eye RT, no stereo composite) — renders a representative
base-game scene correctly, is a **full-frame direct render** (not a composite
half-frame), and is **bit-identical whether or not a stereo configuration is
present**. It also ties parity to the T4.2 psyx reference backend.

## Context

The DX11 renderer is the default for all modes, including monoscopic. When
stereo is disabled the game must render straight to the backbuffer with the
base view-projections — it must not silently route through (or depend on) the
per-eye RTs / `Dx11Stereo_ViewMatrix` / `Dx11Composite` stereo path. This task
proves that mono path is correct and that stereo state variables never leak
into it. The T4.2 store/load A/B already proved the psyx and DX11 backends
render the identical scene from the same world-state (`COMPARE IDENTICAL=PASS`);
T4.3 reuses that same `dx11_backendab_state.h` scene and the psyx reference
BMP to prove base-game parity.

## Design

`spike/dx11_nonstereo_test.cpp` (game-agnostic, on the full DX11 stack, no
stereo/composite modules):

- **Scene**: the T4.2 common world-state default (`Dx11AbScene_FillDefault`) —
  red left bar (0–20%), green centre square (40–60%), blue right bar (80–100%)
  — the same scene the T4.2 psyx reference renders identically.
- **Mono path**: an orthographic screen→NDC view-projection (stored in the
  module's `P^t` convention), flat opaque `twoSided` draw commands, rendered
  **directly into the swapchain backbuffer** (`Dx11Renderer_BindBackbuffer`),
  captured before Present (`Dx11Renderer_CaptureToBMP(…, NULL, …)` = backbuffer).
  No per-eye view, no composite pass.
- Rendered twice: once with stereo **disabled/absent** (NULL config) and once
  with a full stereo **configuration present** (mode=SBS, separation, convergence,
  swap) — the mono path ignores it, so the two frames must be pixel-identical.
- Optional `-psyxref <psyx.bmp>`: probe the T4.2 psyx reference's quad centroids
  against the DX11 mono frame and assert parity.

## Verification

`premake5 gmake2 --os=windows` + `mingw32-make dx11_nonstereo config=release_dev_x86`
(32-bit, the game's known-good PsyCross path). Run `bin/Release_dev/dx11_nonstereo_dev.exe`
at 320x240 (the PSX native res, matching the T4.2 psyx reference BMP). Writes
`dx11_nonstereo_result.txt` (+ `dx11_nonstereo_disabled.bmp` /
`dx11_nonstereo_stereoconfig.bmp`). With the T4.2 psyx reference present:
`-psyxref psyx.bmp` adds the parity probe.

### A/B with the psyx reference (headless)

```
> dx11_backendab_psyx_dev.exe -store -state scene.bin -shot psyx.bmp   (T4.2)
> dx11_nonstereo_dev.exe -psyxref psyx.bmp                            EXIT=0
  MONO  quad0 centroid(32,120)=(220,20,20) expect(220,20,20) PASS
  MONO  quad1 centroid(160,120)=(20,200,40) expect(20,200,40) PASS
  MONO  quad2 centroid(288,120)=(30,60,220) expect(30,60,220) PASS
  FULL_FRAME leftbar(32)=ok rightbar(288)=ok centersq(160)=ok PASS
  STATE_INDEP differing_pixels=0 identical PASS
  PSYX  quad0 centroid(32,120)=(214,19,19) expect(220,20,20) PASS
  PSYX  quad1 centroid(160,120)=(19,194,39) expect(20,200,40) PASS
  PSYX  quad2 centroid(288,120)=(29,58,214) expect(30,60,220) PASS
  PSYX 3/3 centroids match psyx.bmp PASS
  TOTAL_FAILS=0 NONSTEREO=PASS
```

The DX11 mono path renders the base scene correctly (each quad's centroid == its
stored color, exactly), as a full-frame direct render (left/right bars span the
full height, centre square present — not a composite SBS/TB half-frame), and is
pixel-identical with vs without a stereo config present (`differing_pixels=0`).
The mono frame's colours are exact (220,20,20 etc.) vs the psyx reference's
slightly-rounded (214,19,19 etc.) — the same small psyx-readback delta the T4.2
A/B already recorded; both pass the same tolerance, proving parity.

### Bugs found and fixed during verification

- **Second Dx11Renderer creation in one process failed**: the first draft created
  a fresh `Dx11Renderer`/swapchain per frame (once for the disabled frame, once
  for the stereo-config frame), but the second `Dx11Renderer_Create` failed
  (`RENDER stereoconfig FAIL`). The mono path is a single renderer reused frame
  after frame, so the harness now creates one `MonoRenderer` (renderer + res/tex/
  shaders/executor) once and calls `RenderMonoFrame` twice — reusing the same
  device/swapchain. This also matches how the mono path actually runs in the game.
