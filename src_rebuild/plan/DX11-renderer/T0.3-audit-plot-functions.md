## Goal

Map every render-producing game function to the world-space scene data it
already has *before* the GTE transform, so the rewrite can re-point each one to
emit draw commands instead of PSX primitives.

## Context

The plot functions are the capture points. They all follow the same pattern:
fetch world transform + `MODEL` mesh + material → GTE transform → `addPrim`.
This audit is the definitive list of what each function must submit to the
draw-command list, and what is simulated data vs. render-only logic.

Cross-cutting finding: every 3D case already holds full world-space inputs
before the GTE step (world position, rotation, `MODEL`/mesh pointer,
material/texture, animation state). The GTE transform + OT sort are pure
renderer bookkeeping; only the mesh reference, transform and material params
need re-pointing to a draw command. Every function already produces a z-based
OT bucket (`z>>1`, `z>>3`, `z>>8`) that maps directly onto the draw-command
sort key.

## Audit — `RenderGame2` contributors

### Shared world-space data model (capture-point inputs)

- **`MODEL`** (`Game/engine/mdl.h:137`): `SVECTOR* vertices`, `PL_POLYFT4*
  poly_block` (each poly: `texture_set`, `texture_id`, `uv0..uv3`, `id` poly
  type, `th` shading-normal index). Mesh state: `shape_flags`
  (`SHAPE_FLAG_WATER/TILE/SPRITE/TRANS`), `flags2`
  (`MODEL_FLAG_GRASS/PATH/ALLEY/ANIMOBJ/TREE`), `zBias`, `bounding_sphere`.
- **Material resolver:** `texture_pages[texture_set]` (tpage) +
  `texture_cluts[texture_set][texture_id]` (clut) → DX11 texture/material.
- **Transform source:** cell objects carry world `pos` + `yang`; `yang` indexes
  `matrixtable[64]` (pure-Y MATRIX, `CalcObjectRotationMatrices` draw.c:452)
  composed with `inv_camera_matrix` into `CompoundMatrix[yang]`. Cars/dynamic
  objects pass an explicit `MATRIX* matrix` + `VECTOR* pos` to `RenderModel`.
- **Shading:** `combointensity` (ambient) + `SetupPlaneColours` →
  `plotContext.planeColours[8]`/`f4colourTable[32]`; per-poly `th` picks a
  shading slot. `POLYGT3/GT4` + `GetDLightLevel` add per-vertex dynamic light.

**`DrawMapPSX` structure:** `SetupDrawMapPSX` (cell + PVS + frustrum) → spiral
cell sweep, per object `FrustrumCheck16`+PVS cull → classify by `MODEL` flags

Roads are not separate: they are ordinary tile models flagged
`MODEL_FLAG_PATH` drawn through `DrawTILES`/`Tile*`.

## Classification summary

- **(a) world-space geometry/particles → draw command:** all terrain/buildings/
  tiles (`RenderModel`, `Plot*Model*`, `Tile*`, `drawMesh[Lit]`, `DrawSprites`,
  tree shadows), cars (`DrawCar` chain, wheel/spin), events/anim objects, sky
  dome, tyre tracks, smashables, thrown bombs, debris/rain/explosion particles,
  pedestrians (Tanner skinned + Civ billboards), driving-game cones.
- **(b) screen-space overlay/HUD → renderer built-in:** `DrawLensFlare`,
  `AddCopCarLight`, cutscene bars, mission title, `DisplayOverlays`, most of
  `DrawMission` (text/rect), `DrawWorldTargets` markers. Keep world anchor/
  direction as input, project in the renderer.
- **(c) legacy-only (keep for `psyx`):** `PlotMDL_less_than_128`,
  `setupLightingMatrices`/`restoreLightingMatrices`, raw GTE register calls
  (`gte_rtpt`, `gte_stsxy3`, `gte_nclip`, `gte_avsz3`, OT `addPrim`),
  `DrawDebugOverlays`, dead sprite branch in `DrawSmashable_sprites`
  (`UNIMPLEMENTED()`), obsolete D1 water/splash paths.

**Renderer-only logic to preserve regardless:** `makeMesh`/`SubdivNxM`/`TileNxN`
tessellation + LOD selection, `DrawMapPSX` spiral cell + PVS/frustum culling,
`SetupPlaneColours`/`normalIndex`/`ConvertPolygonTypes` shading prep, car wheel
spin deformation, `ofse` grass/water z-offset, `zBias`, semi-transparency, and
`GetDLightLevel` dynamic lighting.
