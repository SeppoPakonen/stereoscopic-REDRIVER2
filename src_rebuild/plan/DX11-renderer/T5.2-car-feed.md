## Scope

The second feed slice of T5.2: rewire the **car** plot path — `DrawCar`
(cars.c) — to submit world-space `DrawCommand`s for the **car body** and the
**wheels** under `-renderer dx11`, while keeping the legacy GTE + `addPrim` path
byte-identical for `-renderer psyx`.

The car body is a **`CAR_MODEL`** (dr2types.h) — a triangulated list of
`CAR_POLY`s (`GT3` body / `FT3` bottom / `B3` bottom) over a shared **dented**
`vlist` (`gTempCarVertDump[cp->id]`), with per-poly textures from the game's
**`civ_clut`** CLUT table (NOT the terrain `texture_pages`/`texture_cluts`
resolve). This is the first poly type the feed handles that is not a flat-quad
`MODEL`, so it adds a new command kind + a new renderer mesh/convert path.

## Design

### World-space convention (critical)

Same as the terrain/tile feed: `DrawCommand.world` is **world space**
(rotation + translation in `t[0..2]`); the renderer builds its own per-eye view.
For a car:
- **Body**: world rotation = `cp->hd.drawCarMat`, world position =
  `cp->hd.where.t` (Y-flipped) **plus the cog offset** (`drawCarMat * cog`,
  matching `DrawCarObject`'s `gte_rtv0tr`). Drawn via `DrawCar`'s LOD branches
  (high → `NewCarModel[model]` with dented `vlist`; low → `NewLowCarModel[model]`).
- **Wheels**: world rotation = `cp->hd.drawCarMat` (rear) or
  `drawCarMat * SteerMatrix` (front, steering), world position =
  `rot * sWheelPos + where.t` (Y-flipped). Wheels are `MODEL` (POLYFT4) so they
  reuse the existing `PlotFeed_SubmitModel` path.

### Feed contract extension

- **`DrawCommand.carModel`** (drawcmd.h): a `struct CAR_MODEL *`; when set
  (`mesh == NULL`) the command is a car body. `palette` (the existing field)
  carries the car's `civ_clut` color variant.
- **`PlotFeed_SubmitCarModel`** (draw.c, declared in draw.h): builds + submits
  the body `DrawCommand` (world = `drawCarMat` + cog'd world pos,
  `sortKey = z>>1`, `palette`).

### Renderer: CAR_MODEL mesh/convert path

- **`Dx11GameFeed_CarModelToMesh`** (dx11_gamefeed.c): converts a `CAR_MODEL`
  (dented `vlist` + GT3/FT3/B3 triangle lists) into the adapter's raw
  `Dx11ModelVertex[]`/`Dx11ModelPoly[]` mesh. Decodes each `CAR_POLY`:
  - `vindices` → 3 vertex indices (8-bit each),
  - packed UVs: `clut_uv0&0xffff` = `(u0|v0<<8)`, `tpage_uv1&0xffff` = `(u1|v1<<8)`,
    `uv3_uv2&0xffff` = `(u2|v2<<8)`; UV X scaled by the tpage page width (`/256`),
  - clut source per kind: **GT3** = `civClut[carid][texid][palette]` (carid =
    `1 + (clut_uv0>>16)/192`, texid = `((clut_uv0>>16)%192)/6`); **FT3** =
    `clut_uv0>>16` (already a VRAM clut address); **B3** = untextured.
  - The poly is emitted as a **triangle** (`vi3 == vi2`), `twoSided`, flat.
- **`Dx11ModelPoly`** (dx11_modeladapter.h/.c): new `carTexture`/`carTpage`/
  `carClut` fields; when `carTexture` is set the adapter **bakes the full page
  region directly** from `carTpage`/`carClut` (page width by tpage format x 256),
  bypassing the terrain/model resolve callback (which only covers
  `texture_pages`/`texture_cluts`).
- **`Dx11GameFeed_RenderFrame`** gained a `civClut` param (`const u_short
  (*)[32][6]`) and a `carModel` branch in its submit loop.

## Integration points

1. `DrawCar` (cars.c): capture the world position (with cog) before the GTE
   camera transform; in each LOD branch submit the body via
   `PlotFeed_SubmitCarModel` (world = `drawCarMat` + cog'd pos, `palette`,
   camera-depth `z`).
2. `DrawCarWheels` (cars.c): per wheel, submit the `MODEL` via
   `PlotFeed_SubmitModel` (world = `drawCarMat`(+steer) + `rot*sWheelPos +
   where.t`).
3. `main.c` `Dx11Game_RenderFrame`: pass `civ_clut` to `Dx11GameFeed_RenderFrame`.

## Non-breaking parallel submit

Same as the terrain/tile core: under dx11 the car path **appends commands and
keeps the GTE draw running** in parallel (the SDL legacy window still shows the
full scene; the DX11 companion window renders the feed).
