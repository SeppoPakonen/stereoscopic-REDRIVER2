## Goal

Implement the remaining stereo composite modes as a per-pixel shader pass:
anaglyph (simple + full-color), interlaced, polarized, checkerboard — building
on the fullscreen composite from T2.3.

## Scope (adjusted with the owner)

The as-written T3.1 ("wire each `gStereoMode` value to the matching shader
variant and verify all modes render on-screen") requires the running game. Per
the owner's decision (same as T1.6–T2.4), T3.1 is scoped to the verifiable
slice: extend the **game-agnostic `dx11_composite` module** (T2.3) with the
color modes as pixel-shader variants of the same fullscreen pass, and extend
the existing `dx11_composite_test.cpp` harness to probe each mode headless.
Wiring `gStereoMode` into the game's DX11 render loop stays a later integration
task.

## Context

The legacy shader compositor (`Game/render/stereo_compositor.c`) was implemented
but disabled because it crashed the GL driver. The DX11 composite pass (T2.3) is
the natural place to add these modes as pixel shader variants, avoiding the
legacy GL shader path entirely. The per-pixel shader already samples the two
eye SRVs (t0/t1) and a `b0` params CB (mode, swap).

## Design

`spike/dx11_composite.{h,c}` (extended). New `Dx11CompositeMode` values ported
verbatim from the legacy shader sources in `stereo_compositor.c`:

- `DX11C_MODE_ANAGLYPH` — simple red-cyan: `(L.r, R.g, R.b, 1.0)`.
- `DX11C_MODE_ANAGLYPH_FULLCOLOR` — luminance-blended: `(L.r*0.8 + Rlum*0.1,
  R.g*0.9 + Llum*0.1, R.b*0.9 + Llum*0.1)` with `Llum = dot(L.rgb,
  (0.3,0.59,0.11))`, `Rlum = dot(R.rgb, (0.3,0.59,0.11))`.
- `DX11C_MODE_INTERLACED` — odd rows = left eye, even rows = right eye
  (`mod(pos.y,2.0) > 0.5` → eye0).
- `DX11C_MODE_POLARIZED` — scanline encoding, complementary: odd rows = right
  eye, even = left.
- `DX11C_MODE_CHECKERBOARD` — `mod(pos.x+pos.y, 2.0) > 0.5` → right eye, else
  left (pixel interleave).

`swap` continues to flip which eye fills each channel/half/row. The harness
(`dx11_composite_test.cpp`, extended) renders eye0 = red / eye1 = blue and
probes each mode: `ANA_S` (magenta), `ANA_FC` (pink-purple), `INT` / `POL`
(adjacent rows alternate red/blue), `CHK` (adjacent pixels alternate), `SWAP`
(anaglyph swap flips channel assignment).

## Verification

`premake5 gmake2 --cc=gcc` + `mingw32-make dx11_composite config=release_x86`
(32-bit; mingw32 runtime DLLs beside the exe). Run `bin/Release/dx11_composite.exe`.
Writes `dx11_composite_result.txt` (sbs / tb / swap / mono + color-mode probes).

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_composite_result.txt:
   SBS_L left-half=(220,0,0) red PASS | SBS_R right-half=(0,0,220) blue PASS
   TB_T top-half=(220,0,0) red PASS | TB_B bottom-half=(0,0,220) blue PASS
   SWAP SBS left=blue right=red PASS | SWAP TB top=blue bottom=red PASS
   MONO full=(220,0,0) red (eye0 pass-through) PASS
   ANA_S center=(220,0,220) magenta PASS
   ANA_FC center=(178,7,205) pink-purple PASS
   INT rows alternate red/blue PASS
   POL rows alternate red/blue (complementary) PASS
   CHK pixels alternate red/blue PASS
   SWAP anaglyph center=(0,0,0) black (channels flipped) PASS
   TOTAL_FAILS=0 COMPOSITE=PASS
```

The composite pixel shader ports the legacy color modes verbatim (anaglyph
simple/full-color, interlaced, polarized, checkerboard) as variants of the T2.3
fullscreen pass. Each samples the two per-eye SRVs and produces the expected
per-pixel pattern — proven headless via pixel probes, with no GL involved.
`SWAP` anaglyph output is black because eye0 (red) has zero g/b and eye1 (blue)
has zero r, so the swapped channel assignment `(R.r, L.g, L.b)` is all-zero —
this confirms the swap flips the channel mapping.

### Bugs found and fixed during verification

No module bugs — the color-mode shader variants matched the legacy sources on
the first build (the interlaced/polarized complementary row assignments were
checked against the legacy `stereo_compositor.c` sources). One harness probe
expectation was wrong and fixed: the `SWAP` anaglyph probe expected blue, but
with the pure-red/pure-blue test eyes the swapped channel assignment renders
black (see above) — corrected to expect black.
