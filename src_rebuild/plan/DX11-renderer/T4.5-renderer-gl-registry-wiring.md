# T4.5 — Wire `-renderer gl` into the registry & build

|            | |
------------|-|
| **Phase**  | Phase 4 — Integration & cleanup |
| **Milestone** | M4 — Integration & cleanup |
| **Status** | done |

## Goal

Add the **modern OpenGL backend** (T4.4's `gl_renderer` mono slice) to the
`-renderer` registry and the game build, so `-renderer gl` resolves and the
`DrawGame` dispatch genuinely selects it — mirroring how T4.1 wired `-renderer
dx11`.

## Context

The renderer registry (`Game/render/renderer.h`) currently knows only
`psyx` / `dx11` (`RENDERER_PSYX` / `RENDERER_DX11`, `Renderer_FromName` /
`Renderer_ToName` / `Renderer_IsPsyX` / `Renderer_IsDX11`). The modern GL
backend exists as the standalone `gl_renderer.{h,c}` module + `gl_nonstereo`
harness (T4.4), proven to render the same scene as DX11. This task brings it
into the registry and the game binary, so the three backends are all selectable
via `-renderer dx11|psyx|gl`. (The GL backend currently renders the mono scene;
per-eye stereo/composite parity remains a further follow-up.)

## Design

Mirror T4.1's slice — the full `DrawGame` → draw-command → GL render-path
rewiring is a later integration task; here we make the selection real and
observable:

1. **Registry** (`Game/render/renderer.h`): add `RENDERER_GL = 2`; resolve
   `"gl"` in `Renderer_FromName`; map it in `Renderer_ToName`; add
   `Renderer_IsGL()`.
2. **Capability probe**: add `GlRenderer_Available()` to `gl_renderer.{h,c}` —
   a lightweight SDL + GL context create/destroy probe (like
   `Dx11Renderer_Available()`), returning nonzero if the modern GL stack is
   usable on this machine. No window/rendering.
3. **Dispatch** (`main.c` `DrawGame`): the `Renderer_IsGL()` branch calls
   `GlRenderer_Available()` and logs the result (the mono path is used for now),
   mirroring the existing dx11/psyx dispatch.
4. **Build** (`premake5.lua` REDRIVER2): add `gl_renderer.{h,c}` to the Windows
   build + the mingw32 SDL2 include (via `MINGW32_SDL2_INCLUDE`, per the T4.4
   gocha). `opengl32`/`SDL2`/glad come from the existing `uses { "PsyCross" }`
   (usage links them + provides `PsyCross/include` for glad.h) — glad is NOT
   re-added to REDRIVER2 (the PsyCross lib already contains `glad.o`; adding it
   would duplicate symbols). `gl_renderer.c` uses the glad symbols from the
   PsyCross lib.
5. **A/B harness**: extend `dx11_rendererselect_test.cpp` to also resolve `gl`
   (`Renderer_FromName("gl") -> GL`, `Renderer_IsGL`) and probe
   `GlRenderer_Available()`.

## Verification

`premake5 gmake2 --os=windows` + `mingw32-make REDRIVER2 dx11_rendererselect
config=release_dev_x86`. The renderer-select A/B is the headless verification
(the full game does not reach `DrawGame` headless, so the dispatch is verified by
the standalone harness + the build-link).

### Renderer-select A/B (headless)

```
> dx11_rendererselect_dev.exe                                     EXIT=0
  SELECT dx11->DX11 PASS | psyx->PSYX PASS | gl->GL PASS
  FLAG   dx11:PASS psyx:PASS gl:PASS
  AVAIL  Dx11Renderer_Available=1 PASS
  AVAIL  GlRenderer_Available=1 PASS
  TOTAL_FAILS=0 RENDERERSELECT=PASS
```

All three backends resolve (`Renderer_FromName`), the `Is*` flags reflect the
selection, and both the DX11 and modern-GL backends are usable on this machine
(`Dx11Renderer_Available`/`GlRenderer_Available` = 1). `REDRIVER2` (release_dev_x86)
compiles `gl_renderer.c` + `main.c` (new gl dispatch) and links OK — the game now
builds with all three backends (dx11 + psyx + gl) in the binary.

### Bugs found and fixed during verification

- **premake `.."/SDL2"` mangling in the REDRIVER2 gcc filter**: the same
  `(os.getenv("MINGW32_INCLUDE") or …) .. "/SDL2"` space bug that broke the T4.4
  GL harness's `SDL.h` also lives in the REDRIVER2 project (masked there because
  the game never `#include <SDL.h>` directly — but `gl_renderer.c` does). Fixed
  the REDRIVER2 filter to prefer `MINGW32_SDL2_INCLUDE` (with the concat as
  fallback), same as the T4.4 projects.
- **glad duplicate-symbol risk**: adding `PsyCross/src/render/glad.c` to the
  REDRIVER2 project would duplicate `gladLoadGL` (the PsyCross lib already
  contains `glad.o`). Only `gl_renderer.{h,c}` are added; glad comes from the
  PsyCross lib.
- **(pre-existing, out of scope) premake `location(JPEG_DIR)` mangles the jpeg
  project's Makefile path** (`jpeg-9d /Makefile`) whenever JPEG_DIR resolves to an
  absolute path, so REDRIVER2's jpeg dependency can't be regenerated by premake.
  The build script tolerates this (no `set -e`); the pre-existing
  `dependencies/jpeg-9d/Makefile` + a patched `build/Makefile` `-C` path were used
  to verify the REDRIVER2 link. Not a code change.
