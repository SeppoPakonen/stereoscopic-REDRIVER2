# T1.1 — DX11 device/context/swapchain + render targets

|------------|-|
| **Phase**  | Phase 1 — Core DX11 renderer |

## Goal

Create the DX11 device/context + a **native Win32 window + DXGI swapchain**
(not SDL2) for the `dx11` backend, plus render-target setup and the per-frame
RT management that Phases 2–3 build on.

## Context

The `psyx` backend keeps the SDL2 GL window. The `dx11` backend is a **native
DirectX stack**: window via Win32 `CreateWindowEx`, presentation via an
`IDXGISwapChain` (replacing `SDL_CreateWindow` + `SDL_GL_SwapWindow`), plus
device/context and render-target objects (backbuffer + offscreen RTs for
stereo). Platform/input/audio are covered by T1.7/T1.8. This task is the
foundation everything else in Phase 1 sits on.

## Scope note: standalone module + harness (not yet the game-boot swap)

The DX11 window/swapchain is delivered as a **reusable, standalone renderer
module** (`spike/dx11_renderer.*`) plus a driving harness
(`spike/dx11_foundation.cpp`), mirroring the T0.5 spike precedent. The game
itself is not yet on the draw-command path (that is T1.5), so swapping the
game's SDL window at boot would break the playable `psyx`/legacy path. The
module is game-agnostic and is adopted into the game boot `-renderer dx11`
branch when the draw-command scene renderer lands (T1.5, with input in T1.7).

## Steps

- [x] Create `ID3D11Device`/`ID3D11DeviceContext` (feature level 11.0+).
- [x] Create the Win32 window (`CreateWindowEx`) + `IDXGISwapChain` for the
      `dx11` backend (no `SDL_CreateWindow`); wire the message loop.
- [x] Create backbuffer RTV + depth/stencil + viewport.
- [x] Add offscreen `ID3D11RenderTargetView`/`ID3D11ShaderResourceView` =
      the internal-resolution RTs (a left/right pair, reusable by T2.1 for
      per-eye).
- [x] Implement present (`IDXGISwapChain::Present`) / clear and resize
      handling (`-res WxH` window, `-ires WxH` internal resolution).
- [x] Module is gated behind the `dx11` backend (delivered standalone; the
      game-boot `-renderer dx11` swap is sequenced with T1.5/T1.7).

## Acceptance criteria

- [x] The module creates device / native Win32 window / DXGI swapchain and

- [x] Offscreen RTs at configurable internal resolution (T0.4) exist (verified

## Deliverables

- `spike/dx11_renderer.h` — public API (lifecycle, queries, per-frame
  begin/present, backbuffer/offscreen bind, offscreen SRV/texture accessors,
  resize, backbuffer capture, raw device/context accessors).
- `spike/dx11_renderer.c` — implementation (compiled as C++ by premake).
- `spike/dx11_foundation.cpp` — standalone harness that drives the module:
  parses `-res WxH` / `-ires WxH` / `-vsync N` / `-fullscreen`, renders a quad
  to the backbuffer and to an offscreen RT at the internal resolution, tests a
  window resize, and captures the results to BMP + pixel-stats files.
- `premake5.lua` — new `dx11_foundation` project (links d3d11/dxgi/d3dcompiler/
  user32/gdi32).

## Verification

Built with `premake5 gmake2 --cc=gcc` + `mingw32-make dx11_foundation
config=release_x86` (32-bit, matching REDRIVER2.exe; needs the mingw32 runtime
DLLs beside it, same as the spike).

Run: `bin/Release/dx11_foundation.exe -res 800x600 -ires 320x240`. The harness
runs 60 frames and writes, relative to the exe:

- `dx11_foundation_info.txt` — effective window + internal sizes.
- `dx11_foundation_back.bmp/.txt` — backbuffer capture (frame 0, before
  Present/DISCARD).
- `dx11_foundation_offscreen.bmp/.txt` — offscreen RT[0] capture at the
  internal resolution (frame 1).
- `dx11_foundation_resize.txt` — resize result + new window size.
- `dx11_foundation_resized.bmp/.txt` — backbuffer capture after resize to
  640x480.

Expected: the backbuffer captures show the centered colored quad over the
clear color; the offscreen capture is 320x240 (the internal resolution), and
the resized capture is 640x480. This proves device/window/swapchain/backbuffer
RTV/DSV/offscreen RTs/present/resize all work under mingw32.

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_foundation_info.txt:        window=800x600 internal=320x240
dx11_foundation_back.txt:        brightPix=43264 bbox=(296,196)-(503,403) Rrange[31,255]  (800x600)
dx11_foundation_offscreen.txt:   brightPix=7056  bbox=(118,78)-(201,161)  Rrange[0,255]   (320x240)
dx11_foundation_resize.txt:      resize=0 window=640x480
dx11_foundation_resized.txt:     brightPix=27652 bbox=(231,151)-(408,328) Rrange[31,254]  (640x480)
```

The quad renders to the 800x600 backbuffer, to the 320x240 offscreen RT[0],
and again to the 640x480 backbuffer after `Dx11Renderer_Resize`.

### Bugs found and fixed during the harness verification

1. **Quad not drawn (brightPix=0).** The harness created the `CULL_NONE`
   rasterizer state but never bound it (`RSSetState` was missing), so the
   default `CULL_BACK` culled the two-sided quad. Fixed by storing the
   rasterizer state in the scene and binding it before each draw.
2. **`ResizeBuffers` returned `DXGI_ERROR_INVALID_CALL` (resize code 4).** The
   resize path released the backbuffer RTV but not the still-referenced
   backbuffer texture (`backTex`), so the swapchain could not resize. Fixed by
   releasing both `backRTV` and `backTex` before `ResizeBuffers`.
3. **Harness hung on `Present(1,0)` headless** (frame counter never reached the
   resize step). Present with vsync blocks when the window is not visible in
   this launch context. The harness defaults to `vsync=0` so it runs to
   completion; the game can still opt into vsync via `-vsync 1`.

### Notes

- Uses the row-vector x column-major convention and `M[2][3]` world-Z
  translation learned in T0.5.
- Captures the backbuffer **before** `Present` (DXGI_SWAP_EFFECT_DISCARD).
