# T2.2 — Per-eye projection (yaw-derived lateral offset)

|            | |
------------|-|
| **Phase**  | Phase 2 — Stereo natively |
| **Milestone** | M2 — Stereo natively |
| **Status** | planned |

## Goal

Apply the per-eye view offset to the DX11 projection, reusing the yaw-derived
lateral offset math (`right=(cos θ,0,sin θ)`, left `-right`, right `+right`)
from the stereo work, plus the convergence/separation parameters.

## Context

The proven stereo camera math must be reused verbatim. The offset axis is the
camera-yaw lateral axis because `camera_matrix` column 0 is the view axis and is
distorted by the aspect matrix. The DX11 renderer builds a per-eye view matrix
from `camera_position`/`camera_angle` + the eye offset, then the projection from
T0.4.

## Steps

- [ ] Port the eye-offset math from `StereoCamera_ApplyToRender` into the DX11
      per-eye view construction (or call it directly).
- [ ] Build the per-eye view matrix (world→view) from `camera_matrix`/offset.
- [ ] Fold `gStereoConvergence`/`gStereoSeparation`/`gStereoSwapEyes` into the
      per-eye projection.
- [ ] Verify the two eyes differ only by the lateral offset (camera stable).
- [ ] Confirm the right-eye geometry is present (prims/draws equal both eyes).

## Acceptance criteria

- [ ] Both eyes render the full scene with only a stable lateral offset.
- [ ] Convergence/separation/swap-eyes affect the projection as expected.
- [ ] The right-eye "map disappears" symptom is absent in DX11.
