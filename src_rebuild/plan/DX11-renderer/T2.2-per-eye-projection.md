## Goal

Build the DX11 per-eye projection as a game-agnostic stereo-camera module that
reuses the proven yaw-derived lateral-offset math verbatim, plus a headless
harness that verifies the two eyes differ only by a stable lateral offset and
that separation / swap-eyes / convergence behave as expected.

## Scope (adjusted with the owner)

The as-written T2.2 ("fold the game's `camera_matrix` / `gStereo*` globals into
the running DX11 renderer and confirm the right-eye map is present in-game")
requires the running game. Per the owner's decision (same as T1.6–T2.1), T2.2 is
scoped to the first verifiable slice: a **game-agnostic per-eye projection
module + headless harness** that ports `StereoCamera_ApplyToRender`'s eye-offset
math verbatim and verifies the per-eye view/projection math. Wiring it into the
game's DX11 render loop (with the real `camera_matrix`/`gStereo*` globals) and
the in-game right-eye check move to the integration task (T2.4).

## Context

`StereoCamera_ApplyToRender` (`Game/render/stereo.c`) computes the per-eye
offset from the camera yaw:
```
forward = (sin θ, 0, -cos θ),  right = (cos θ, 0, sin θ)
theta = camera_angle.vy & 0xFFF,  in binary degrees (2π = 4096)
offset = gStereoSeparation * 2.0f           (world units)
ax = (eye == LEFT) ? -cos θ : +cos θ        (swap flips the sign)
az = (eye == LEFT) ? -sin θ : +sin θ
camera_position += (ax, 0, az) * offset
```
`gStereoConvergence` is applied renderer-side as a **projection shear** (a
horizontal screen shift), not on the camera path. `gStereoSwapEyes` negates the
offset sign.

## Design

`spike/dx11_stereo.{h,c}` (game-agnostic; the game shim passes the camera yaw /
position / params):

- `Dx11Stereo_EyeOffset(yawRad, eye, separation, swap, out[3])` — the world-space
  lateral offset, replicating the legacy math verbatim: `right=(cos θ,0,sin θ)`,
  `gain = separation*2`, left → `-right·gain`, right → `+right·gain`, `swap`
  negates. `MONO` → 0.
- `Dx11Stereo_ViewMatrix(camPos[3], yawRad, eye, separation, swap, mat)` —
  world→view matrix for an eye (rotation basis `right/up/-forward` from the yaw,
  translation `-R·eyePos` where `eyePos = camPos + EyeOffset`). Returns the
  **transposed view `V^t`** (basis in the columns, translation in the last row)
  so that `viewProj = view * proj` composes to `(P*V)^t` under the DX11
  pipeline convention (proj stored as `P^t`).
- `Dx11Stereo_ApplyConvergence(float mat[4][4], float shift)` — shear a
  perspective projection by a horizontal screen offset (convergence): for each
  column `i`, `mat[0][i] += shift · mat[3][i]` (shifts `clip.x` by `shift·clip.w`).

The harness (`spike/dx11_stereo_test.cpp`):
- `EYE_OFF` — at yaw 0, left offset = `(-sep·2, 0, 0)`, right = `(+sep·2, 0, 0)`,
  mono = 0; at a non-zero yaw the offset is `±gain·(cos θ, 0, sin θ)`.
- `STABLE` — the left and right **view matrices differ only in the last-row
  translation** (the lateral axis), by exactly `4·separation`; the 3×3 basis is
  identical (camera stable).
- `SWAP` — swapping eyes flips the offset sign.
- `SEP` — doubling the separation doubles the offset (proportional).
- `CONV` — `ApplyConvergence` changes the projection horizontally and is
  proportional to `shift`.

```
dx11_stereo_result.txt:
   EYE_OFF mono=(0,0,0) PASS | left=(-2,0,0) PASS | right=(2,0,0) PASS
   EYE_OFF yaw=0.4 left=(-1.842,-0.779) == right=(cos,0,sin)*gain PASS
   STABLE rotation part identical PASS
   STABLE last-row x-trans diff=-4.000 expect -4.0 PASS
   STABLE last-row y/z trans identical PASS
   SWAP left offset flips (-2 -> 2) PASS
   SEP offset(sep=2)=-4 == 2*offset(sep=1) PASS
   CONV shear row0 += shift*row3 PASS
   CONV proportional (0.2 = -0.2, 0.1 = -0.1) PASS
   TOTAL_FAILS=0 STEREO=PASS
```

`Dx11Stereo_EyeOffset` reproduces the legacy `StereoCamera_ApplyToRender` math
verbatim (right = `(cos θ,0,sin θ)`, gain = `sep*2`, left → `-right·gain`, right →
`+right·gain`, swap negates). The left/right **view matrices differ only in the
last-row (lateral-axis) translation by exactly `4·separation`** while the 3×3
basis and the other translations are identical — the camera is stable and the
eye offset is purely lateral. `Dx11Stereo_ApplyConvergence` shears the
projection horizontally (`row0 += shift*row3`) proportionally to `shift`.

### Bugs found and fixed during verification

**Updated after T2.4 (integration):** `Dx11Stereo_ViewMatrix` originally
returned the standard column-vector view matrix `V` (translation in the last
column). The T2.4 stereo-scene harness proved this did not compose with the
DX11 pipeline's `P^t` projection convention — the eye offset folded into the
projection w-axis and the lateral parallax rendered ~3x too large. Fixed to
return the transposed `V^t` (basis in columns, translation in the last row),
updated the `STABLE` probes to check the last-row translation, and re-verified
(`STEREO=PASS`). The pure-math T2.2 test could not catch this itself.
