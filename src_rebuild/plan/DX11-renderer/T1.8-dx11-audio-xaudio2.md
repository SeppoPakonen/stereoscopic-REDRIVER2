## Goal

Build the DX11 backend's audio layer as a game-agnostic **XAudio2 module**:
an `IXAudio2` engine + mastering voice, per-buffer source voices, and a PCM
buffer API (play/stop, volume, pan) — verified headless with a dedicated
harness, following the same standalone-module pattern as T1.1–T1.7.

## Scope (adjusted with the owner)

The original T1.8 ("port the PSX SPU emulation `PsyX_SPUAL.cpp` to XAudio2 and
verify gameplay audio under `-renderer dx11`") requires the running game and
full SPU emulation. Per the owner's decision (same as T1.6/T1.7), T1.8 is
scoped to the first verifiable slice: a **game-agnostic XAudio2 audio module +
headless harness**. Porting `PsyX_SPUAL.cpp` (and the `utils/audio_source/`
WAV sources) onto the module, and the in-game `-renderer dx11` audio wiring,
move to a follow-up task.

## Context

Audio is already decoupled from SDL2: it is OpenAL (`PsyCross/src/audio/PsyX_SPUAL.cpp`,
`utils/audio_source/snd_al_source.*`), which stays for the GL backends. The DX11
"pure DirectX" goal swaps it to XAudio2. The module stays game-agnostic: it
exposes the same sound-source primitives the OpenAL path offers (create a voice
for a PCM format, submit raw PCM samples with optional looping, play/stop, set
volume/pan) so the later game shim can map the SPU calls onto it. mingw32 has
`xaudio2.h` + `libxaudio2_8.a` (link `-lxaudio2_8`).

XAudio2 2.8 uses `XAudio2Create` (not the old `CoCreateInstance(CLSID_XAudio2)`).

## Design

`spike/dx11_audio.{h,c}`:

- `Dx11Audio_Create(Dx11AudioResult*)` — `CoInitializeEx`, then
  `XAudio2Create`, then `CreateMasteringVoice`. A missing audio output device is
  reported (the module still returns the engine; `HasOutput` reflects the
  mastering voice).
- `Dx11Audio_CreateVoice(audio, channels, sampleRate, Dx11AudioVoice**)` — a
  source voice with the given format (`WAVEFORMATEX`, PCM).
- `Dx11Audio_SubmitBuffer(voice, const void *pcm, int pcmBytes, int loop)` —
  queue raw PCM samples (optionally looping: `XAUDIO2_LOOP_INFINITE`).
- `Dx11Audio_Play(voice)` / `Dx11Audio_Stop(voice)` — `Start`/`Stop`.
- `Dx11Audio_SetVolume(voice, float)` — 0..1 (`SetVolume`).
- `Dx11Audio_SetPan(voice, float)` — −1..1, mapped to the 2-channel output
  matrix via `SetOutputMatrix` (left/right gains).
- `Dx11Audio_DestroyVoice` / `Dx11Audio_Destroy`.

The harness (`spike/dx11_audio_test.cpp`):
- Creates the audio engine + mastering voice (skips the play probes and reports
  SKIP if no audio output device exists).
- Builds a short 16-bit PCM sine wave, creates a source voice, submits it,
  plays, pauses ~50 ms, and verifies the voice is running (`GetState`).
- Exerts `SetVolume`/`SetPan` on a second buffer and verifies no crash.
- Destroys everything cleanly.

## Verification

`premake5 gmake2 --cc=gcc` + `mingw32-make dx11_audio config=release_x86`
(32-bit; mingw32 runtime DLLs beside the exe). Run
`bin/Release/dx11_audio.exe`. Writes `dx11_audio_result.txt` (engine/voice/play
probes + PASS/FAIL/SKIP).

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_audio_result.txt:  ENGINE create (result=0 expect 0) PASS
                       ENGINE mastering voice present
                       VOICE mono 44100 create PASS
                       PLAY submit sine buffer PASS
                       PLAY start PASS
                       PLAY buffer in flight after Start PASS
                       PLAY buffer drained after 0.9 s PASS
                       VOLPAN set volume/pan (voice create ok) PASS
                       DESTROY voices + engine clean PASS
                       TOTAL_FAILS=0 AUDIO=PASS
```

The XAudio2 module CoInitializeEx + XAudio2Create + CreateMasteringVoice (an
audio output device is present), creates a mono 44100 source voice, submits a
0.5 s 16-bit sine buffer, starts it (the buffer is in flight immediately after
`Start` and drains to zero after it finishes), and handles volume/pan on a
second voice without crashing. Play probes would be SKIPped on a machine with
no audio output device.

### Bugs found and fixed during verification

No link/runtime bugs (the `-lxaudio2_8` link and the XAudio2 2.8
`XAudio2Create` API are correct). One design refinement: XAUDIO2 has no direct
"playing" flag, so `Dx11Audio_IsPlaying` reports a voice as playing via
`GetState().BuffersQueued > 0` (a submitted buffer the engine hasn't consumed),
which drops to 0 once the buffer finishes.
