## Goal

Keep the mingw32 build and the headless iteration harness working with the new
`-renderer` selection, so the DX11 stereo path is verifiable the same way the
legacy path was.

## Scope (adjusted with the owner)

The as-written T4.1 ("run a mission under both renderers and log per-eye draw
counts + an A/B screenshot from the full DX11 render path") requires wiring the
entire `DrawGame` → draw-command → DX11-RT → per-eye → composite path into the
game, which is the whole rewrite's core integration. Per the owner's decision,
T4.1 is scoped to the **build + `-renderer` headless slice**: make the DX11
renderer stack compile and link into the game binary within the existing 32-bit
mingw32 toolchain, and make the `DrawGame` backend dispatch genuinely select
`dx11` vs `psyx` (the dx11 branch now calls a real DX11-module function and logs
it, instead of the old "legacy fallback until Phase 1" comment). The full
draw-path rewiring stays a later integration task.

## Context

The renderer registry (`Game/render/renderer.h`, T0.1) already parses
`-renderer dx11|psyx` into `gRenderer` and exposes `Renderer_IsDX11()` /
`Renderer_IsPsyX()`. But `DrawGame` (main.c) currently just logs "legacy
fallback until Phase 1" for both — the DX11 branch is a dead comment and the
DX11 modules are not part of the game build. This task fixes both: the modules
compile/link into the game, and the dispatch genuinely selects the backend.

## Design

- **Build (premake REDRIVER2 project)**: add the 8 core DX11 modules
  (`dx11_renderer`, `dx11_resources`, `dx11_textures`, `dx11_shaders`,
  `dx11_drawcmdexec`, `dx11_modeladapter`, `dx11_stereo`, `dx11_composite`) to
  the Windows build's `files` + the `d3d11`/`dxgi`/`d3dcompiler`/`user32`/
  `gdi32` links. The harness/test files (`dx11_*_test.cpp`) are NOT added (they
  define their own `WinMain`; the game has the real entrypoint).
- **Dispatch (main.c `DrawGame`)**: the `Renderer_IsDX11()` branch calls
  `Dx11Renderer_Available()` (a new real function in `dx11_renderer` that
  attempts a `D3D11CreateDevice`) and logs the result; the `psyx` branch runs
  the legacy path. Both still render the game (dx11 stays on the legacy path for
  now) but the selection is real and observable in `stereo_iter.log`.
- **Headless A/B**: run the game under `-renderer dx11` and `-renderer psyx`
  headless and confirm the iteration log reports the correct backend.

## Verification

`premake5 gmake2 --os=windows` + `mingw32-make REDRIVER2 config=release_dev_x86`
(the `build_release_mingw32.sh` path, 32-bit). The headless A/B is the
`dx11_rendererselect` harness.

### Actual observed output (mingw32 32-bit, release_dev_x86)

```
build:  (REDRIVER2 project, 8 DX11 modules compiled in + linked)
   drawcmd.c dx11_composite.c dx11_drawcmdexec.c dx11_modeladapter.c
   dx11_renderer.c dx11_resources.c dx11_shaders.c dx11_stereo.c dx11_textures.c
   main.c ... Linking REDRIVER2 OK

dx11_rendererselect_result.txt:
   SELECT dx11->DX11 PASS | psyx->PSYX PASS
   FLAG dx11:PASS psyx:PASS
   AVAIL Dx11Renderer_Available=1 PASS
   TOTAL_FAILS=0 RENDERERSELECT=PASS
```

The game builds and links with the DX11 renderer stack compiled in (32-bit
mingw32 toolchain), and `DrawGame` now genuinely dispatches on `-renderer dx11`
vs `-renderer psyx`, calling `Dx11Renderer_Available()` in the dx11 branch and
logging the result. The headless A/B harness verifies both backends resolve
correctly (`Renderer_FromName`/`IsDX11`/`IsPsyX`), and that the DX11 stack is
usable on this machine (`Dx11Renderer_Available()=1`).

Running the full game headless to observe the live `DrawGame` iteration-log line
was attempted but the game did not reach the gameplay loop within the run window
(no `stereo_iter.log`), so the two-backend selection is verified by the
standalone A/B harness plus the dispatch code (which is wired and correct by
inspection). The full in-game draw-path A/B remains a later integration task.

### Bugs found and fixed during verification

No module bugs. Notable build steps: the game's exec now imports `d3d11.dll` /
`D3DCOMPILER_47.dll` (from the DX11 modules) plus `libopenal-1.dll`/`SDL2.dll`;
running the game required those runtime DLLs beside the exe. The `DrawGame`
dispatch previously had no real DX11 branch (dead "legacy fallback" comment);
wiring it to `Dx11Renderer_Available()` required adding that function to
`dx11_renderer` and the DX11 sources + links to the REDRIVER2 build.
