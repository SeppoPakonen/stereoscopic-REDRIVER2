# T1.2 — Resource management (VB/IB, CBs, SRVs, arena)

|            | |
|------------|-|
| **Phase**  | Phase 1 — Core DX11 renderer |
| **Milestone** | M1 — Core DX11 renderer |
| **Status** | planned |

## Goal

Implement DX11 resource management: vertex/index buffers, constant buffers,
shader-resource views, sampler state, and a per-frame arena that backs the
draw-command list and its vertex data.

## Context

The draw-command list (T0.2) is per-frame. The renderer needs a way to pack
world-space vertices into GPU buffers and bind per-draw state (world transform,
material, camera) via constant buffers. A per-frame arena lets the game submit
commands/vertices each frame without per-object allocation.

## Steps

- [ ] Per-frame arena allocator for the draw-command list (growable, cleared
      each frame).
- [ ] Vertex buffer (dynamic/update) + index buffer management for submitted
      geometry (world-space vertices from the `MODEL` meshes).
- [ ] Constant buffer layout (world/view/projection per eye, material params,
      camera) and per-draw binding.
- [ ] SRV + sampler management (textures from T1.3).
- [ ] Cleanup/free paths (device teardown, frame-buffer rotation for double
      buffering).

## Acceptance criteria

- [ ] The game can submit N draw commands with vertices each frame into the arena.
- [ ] Per-draw VB/CB binding works; buffers are reused without per-frame leaks.
- [ ] Frame-over-frame allocation is bounded (no unbounded growth).
