# T4.2 — Keep legacy `psyx` path selectable

|            | |
------------|-|
| **Phase**  | Phase 4 — Integration & cleanup |
| **Milestone** | M4 — Integration & cleanup |
| **Status** | planned |

## Goal

Keep the legacy PsyX/PsyCross GL renderer (`-renderer psyx`) compilable,
selectable and functional as the reference/fallback backend while the DX11
renderer becomes the default.

## Context

By design the OT/primitive stream survives only behind `psyx`. This task
guards that the DX11 rewrite does not break it: the game's plot functions get
DX11 draw-command branches without removing their `psyx` addPrim behavior, and
the psyx GL sources stay in the build.

## Steps

- [ ] Ensure every plot-function change is gated so the `psyx` path still emits
      GTE+addPrim and `DrawOTag` unchanged.
- [ ] Confirm the psyx GL sources (`PsyX_GPU.cpp`, `PsyX_render.cpp`,
      `LIBGPU.C`, `glad.c`) still compile and link.
- [ ] Run a mission under `-renderer psyx` and confirm identical legacy output.
- [ ] Document the psyx backend as the reference/fallback in `PRODUCT.md`.

## Acceptance criteria

- [ ] `-renderer psyx` reproduces the pre-rewrite visual behavior exactly.
- [ ] Both backends coexist in one build; no shared-state regressions.
- [ ] The registry clearly selects between them.
