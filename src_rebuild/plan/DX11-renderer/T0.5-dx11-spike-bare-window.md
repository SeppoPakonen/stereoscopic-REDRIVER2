## Goal

Prove the core DX11 stack works end-to-end before building the real converter:
a bare DX11 window/swapchain that draws a single meshed quad from one draw
command, using the projection model from T0.4.

## Context

This de-risks the largest unknowns (vs. the SDL2-GL window init): DX11 device
creation on this machine, swapchain + RT setup, shader compile, and rendering a
small VB from a draw command. It validates the toolchain (mingw32 32-bit + the
DX11 headers/libs) early.

## Steps

- [x] Scaffold a standalone DX11 test (device/context/swapchain, RT, viewport).
- [x] Add a minimal vertex/pixel shader pair (position + color).
- [x] Build one quad into a VB/IB and issue a single draw of it.
- [x] Render it to the swapchain and present; verify the window shows the quad

## Verification

Built with `premake5 gmake2 --cc=gcc` + `mingw32-make dx11_spike config=release_x86`
(32-bit, matching REDRIVER2.exe). The spike links `-ld3d11 -ldxgi -ld3dcompiler`
(mingw32 import libs, all present in `I:\msys64\mingw32\lib`).

Run: `bin/Release/dx11_spike.exe` (needs the mingw32 runtime DLLs
`libgcc_s_dw2-1.dll`, `libstdc++-6.dll`, `libwinpthread-1.dll` beside it, copied
from `I:\msys64\mingw32\bin`). On the first frame the spike writes
`bin/Release/dx11_spike_frame.bmp` + `dx11_spike_frame.txt`.

Verified output (`dx11_spike_frame.txt`):
```
brightPix=67600 bbox=(270,170)-(529,429) Rrange[31,255]
OK 800x600
```
The BMP shows a centered quad with the four vertex colors (red/green/blue/yellow)
blended across it — the full VB/IB → input-layout → VS(projection CB) → PS →
RTV pipeline works. The quad is drawn with the T0.4 right-handed projection
(fovY from aspect, −Z forward).

### Bugs found during the spike (build for Phase 1)

1. **`CreateBuffer(CB)` → E_INVALIDARG (0x80070057).** Fixed by providing
   initial data (identity matrix) instead of `pSysMem = NULL` for the
   `D3D11_USAGE_DEFAULT` constant buffer.
2. **Quad not visible despite correct projection.** Root cause was a
   matrix-convention error: with row-vector × column-major math, a world
   z-translation belongs at `M[2][3]`, not `M[3][2]` (which is the `w = −z`
   term in the projection). This is the same convention the T0.4 projection
   uses, so Phase 1 must keep `M[2][3]` for translation and `M[3][2] = −1`.
3. **Present/DISCARD capture timing:** after `Present` with
   `DXGI_SWAP_EFFECT_DISCARD` the back-buffer contents are undefined; capture
   must read the back buffer *before* present.
