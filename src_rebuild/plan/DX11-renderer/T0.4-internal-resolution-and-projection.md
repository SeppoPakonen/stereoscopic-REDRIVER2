## Goal

Define the configurable internal-resolution model and how the view/projection
matrix is built per viewport and per eye, decoupled from the PSX 320x240 GTE
projection.

## Context

The PSX GTE bakes a 320x240 (NTSC) / 320x256 (PAL) projection into the math
(`scr_z` focal length, `OFX=160`, `OFY=height/2`), which is why the legacy
offscreen is resolution-locked. The DX11 renderer builds its own projection
from the camera (`camera_position`, `camera_angle`, `camera_matrix`) and the
per-eye lateral offset (`right=(cos θ,0,sin θ)`), so internal resolution becomes
free. This task freezes the projection math and the resolution config.

## Current GTE math (the baseline to reproduce)

**Camera state** (`Game/C/camera.c:12-16`):
- `camera_position` — `VECTOR` (int32 world pos).
- `camera_angle` — `SVECTOR` (int16 **YXZ Euler, binary degrees**, 0..4096 = 2π).
- `camera_matrix` / `inv_camera_matrix` — 3×3 int16 (`ONE=4096` fixed point) + `t[3]`.

**View matrix** (`convert.c:67-98` `BuildWorldMatrix`):
```c
inv_camera_matrix = aspect · RotMatrixY(camera_angle.vy)
                            · RotMatrixZ(camera_angle.vz)
                            · RotMatrixX(camera_angle.vx);   // rotation-only view
camera_matrix = transpose(inv_camera_matrix);                 // pure transpose (rotation)
```
`aspect` = identity on NTSC, `diag(4096,4300,4096)` on PAL. World→camera:
```
cam = inv_camera_matrix · (p_world − camera_position)
```

**Projection / perspective** (`PsyX_GTE.cpp:380-397` `GTE_RotTransPers`):
- `scr_z` focal length in pixels (default 256, `gCameraDefaultScrZ`).
- `SetGeomOffset(160, height/2)` → OFX=160, OFY=120 (NTSC) / 128 (PAL).
- Net effect (the classic PSX pinhole, all fixed-point cancelling):
```
screen_x = 160 + scr_z · cam_x / cam_z
screen_y = ofy + scr_z · cam_y / cam_z          // screen origin top-left, Y down
```
- Depth: OT `SZ = cam_z · 2048`, clamped to unsigned 16-bit `[0,0xffff]`.
- FOV: `tan(halfFOV_x) = 160/scr_z`, `tan(halfFOV_y) = ofy/scr_z`. scr_z=256 ⇒
  half-FOV_x ≈ 32°. `FrAng = ratan2(160, scr_z)` (main.c:2478) is only the PC
  widescreen **cull** FOV; the actual projection is unchanged.

**Coordinate conventions (`RenderGame2`, main.c:2461):**
- Right-handed; camera space **+X right, +Y up, +Z forward** (into screen).
- View basis from `RotMatrixY` at yaw θ:
  `right=(cosθ,0,sinθ)`, `up=(0,1,0)`, `forward=(-sinθ,0,cosθ)`.
- The game negates Y between physics/world storage and render in many places
  (`pos.vy = -cp->hd.where.t[1]` cars.c:1419; `basePos[1] = -event->position.vy`
  camera.c:106). Net effect: render-side "up" is fed to the GTE as −Y, and the
  projection renders it upright. So the render-side Y-up maps to GTE −Y.

**Stereo per-eye offset** (`Game/render/stereo.c:118-160` `StereoCamera_ApplyToRender`):
- Translation-only (parallel, no toe-in), applied to `camera_position` after
  `InitCamera` and before `Set_Inv_CameraMatrix`/`SetCameraVector`:
```
θ = (camera_angle.vy & 0xFFF) · (2π / 4096)
right = (cos θ, 0, sin θ)
Δeye = ± gStereoSeparation · 2 · right         // + for RIGHT, − for LEFT (swap-aware)
camera_position.vx += Δeye.x; camera_position.vz += Δeye.z;
```
- `gStereoConvergence` is **not** used on this camera path (only in the
  `stereo_quality.c` shader path). It stays a renderer-side convergence param.
- `StereoCamera_ApplyEyeOffset` (stereo.c:44-70) is a dead/duplicate path whose
  result is ignored — to be cleaned up, not reused.

## Projection model (DX11)

### View matrix
Reuse the existing rotation-only `inv_camera_matrix` basis (right/up/forward)
and `camera_position` translation:
```
R  = rows { right, up, forward }  = inv_camera_matrix (3×3, normalized)
T  = −R · camera_position
View = [ R  T ]                     // 4×4, world → camera
```
The camera-right vector for per-eye offset is exactly `row 0` of `R`
(`right=(cosθ,0,sinθ)`), so the existing `(cosθ,0,sinθ)` math is preserved.

### Projection matrix
Reproduce the pinhole `screen = of + scr_z·cam/cam_z` in NDC. Using a
standard perspective matrix with focal length in pixels:
```
fov_y  = 2 · atan(ofy / scr_z)          // vertical FOV from the GTE focal
aspect = (W / 2) / (H / 2) = W / H      // internal resolution aspect
near   = scr_z / 4096                   // ≈ GTE near (divide-table limit, camera units)
far    = 0xffff / 2048 ≈ 32             // GTE depth clamp (cam_z units)
m00 = f / aspect,  m11 = f,  f = ofy / tan(fov_y/2) = scr_z
m22 = far/(near−far),  m23 = near·far/(near−far)
```
This yields `proj · cam = (cam_x·f/aspect, cam_y·f, a·cam_z+b, ±cam_z)` matching
`scr_z·cam/cam_z` up to the NDC divide and viewport scale.

### Handedness / coordinate mapping (GTE → DX11 NDC)
- GTE camera space is **right-handed, +Z forward**. A standard DX11 right-handed
  projection looks down **−Z**. Two consistent options:
  1. **Negate camera Z** in the view matrix (`R.row2 = −forward`), keep +Y up,
     use a right-handed projection with clip z near = −1 / far = 1. This is the
     least surprising for a right-handed DX11 pipeline.
  2. Use a left-handed projection (+Z forward maps to NDC z=0..1) and keep the
     GTE basis unchanged.
  Recommend **option 1** (right-handed, standard DX11): view = `R{right, up,
  −forward}`, so the scene's +Z-forward GTE depth becomes the −Z-forward DX11
  convention, and the OT depth map (`cam_z`) is preserved as the sort key.
- **Y axis:** GTE render-side "up" is fed as −Y; the DX11 pipeline must flip Y
  so screen-up stays up. Apply the same Y-negation the game already applies to
  world positions before the view transform (keep `pos.vy = -world.vy`), or
  equivalently negate the Y row of the view matrix. **Do not flip again** in the
  projection — the NDC viewport maps Y-up to screen-up.
- **Screen origin / Y-down (GTE) vs NDC / Y-up (DX11):** handled by the
  viewport transform, not extra math. The projection's +Y-up NDC maps to
  screen-up via the viewport; the GTE's top-left origin is reproduced by the
  viewport `(0, H)` flip in the composite.
- **Depth/sort:** the draw-command sort key keeps the GTE `cam_z` convention
  (larger = farther); the renderer sorts opaque front-to-back / transparent
  back-to-front on that key. The DX11 depth buffer uses the NDC z (near=1,
  far=0 for right-handed, or 1..0 inverted) — the two are independent: depth
  buffer for write/occlusion, sort key for draw order.

### Per-eye projection
Reuse `StereoCamera_ApplyToRender` exactly: translate `camera_position` by
`±gStereoSeparation·2·right` (swap-aware) **before** building the view matrix.
No toe-in on the camera path. Convergence:
- `gStereoConvergence` is applied **in the renderer** as a projection shear
  (asymmetric frustum) shifting each eye's projection toward the convergence
  distance, matching the existing `stereo_quality.c` shader behavior. The
  camera-side translation stays parallel (physiological).
- For the DX11 path, expose `gStereoSeparation` (camera Y-translation) and
  `gStereoConvergence` (projection shear) as the two independent controls.

### Internal resolution
- Config: `-res WxH` (CLI) / `internalResolution` (config key). Default = window
  client size (or a sane floor, e.g. 320×240 for parity first, then 640×480+).
- Independent of eye count: each eye renders to a full internal-resolution RT;
  SBS/TB composite scales per-eye halves into the swapchain (Phase 2).
- The renderer owns the RT selection; the GTE 320×240 lock is gone.
