# T1.4 — Shaders + render state

|            | |
|------------|-|
| **Phase**  | Phase 1 — Core DX11 renderer |
| **Milestone** | M1 — Core DX11 renderer |
| **Status** | done |

## Goal

Implement the DX11 shaders and render state that reproduce the PSX/PsyX
appearance: flat & gouraud shading, texture sampling, alpha/semi-transparency,
depth, blending, and the draw modes the game uses.

## Context

The legacy `Process*` handlers in `PsyX_GPU.cpp` distinguish flat vs gouraud
(bit 0 of the code), semi-transparency (bit 1), textured vs untextured, and
blend modes. The DX11 vertex/pixel shaders must cover these so the draw-command
paths from T0.3 render faithfully.

## Scope note: delivered as a standalone module + harness (like T1.1 / T1.2 / T1.3)

The shader + render-state layer is `spike/dx11_shaders.{h,c}` (game-agnostic),
driven by `spike/dx11_shaders_test.cpp` on top of the `dx11_renderer` foundation
and the `dx11_textures` module (for real SRVs). Adopted into the game
draw-command renderer in T1.5.

## Design notes

- **One universal VS** (world→view→projection via b0/b1 from the T1.2 resource
  manager) + **two pixel shaders** — a flat-mode PS (constant color from a
  per-draw `b2` CB) and a gouraud-mode PS (interpolated vertex color). Both
  multiply by the sampled texture. **Untextured surfaces bind the T1.3 white
  1x1 substitute**, so `white * color = color` — one textured PS covers both
  textured and untextured, matching the psyx `color * v_color` combine.
- **Blend + depth-stencil states mirror the PSX table** (from `GR_SetBlendMode`):
  - `BM_NONE` → no blend, depth write on.
  - `BM_AVERAGE` → `src*srcAlpha + dst*(1-srcAlpha)` (SRC_ALPHA/INV_SRC_ALPHA).
  - `BM_ADD` → `src + dst` (ONE/ONE, ADD).
  - `BM_SUBTRACT` → `dst - src` (ONE/ONE, SUBTRACT).
  - `BM_ADD_QUATER_SOURCE` → `src*0.5 + dst` (BLEND_FACTOR/ONE) — matches the
    0.5 constant alpha the GL path actually uses.
  - Translucent polys get depth-write-off (ordered by the OT sort key in T1.5).
- **Alpha / semi-transparency.** The psyx shader does `t.w = 1.0 - t.w` on the
  `rgLUT` alpha (`stp << 7`), so a texture's final alpha is `1 - stp*0.5`
  (1.0 opaque, 0.5 if the palette entry's stp bit is set). T1.3's bake fixed
  alpha to 255; **T1.4 corrects it to `stp ? 128 : 255`** so semi-transparent
  textured polys blend faithfully. Untextured semi-trans polys set the flat /
  vertex alpha directly (0.5).
- Compile errors surface via a message box + exit in the harness (no hot-reload
  yet; the shaders are embedded HLSL strings, so a rebuild is a recompile).

## Acceptance criteria

- [x] Flat and gouraud polys, textured and untextured, render correctly
      (probed in the harness).
- [x] Semi-transparent surfaces blend like the `psyx` reference
      (center-probe = 0.5 mix verified).
- [x] Depth is correct for opaque geometry (opaque depth-write state; ordering
      is the T1.5 sort-key job).

## Deliverables

- `spike/dx11_shaders.h` / `spike/dx11_shaders.c` — universal VS + flat/gouraud
  textured PS, input layout (matches `Dx11ResVertex`), 5 blend states, 2
  depth-stencil states (opaque / translucent), 2 rasterizer states (cull /
  two-sided), per-draw flat-color CB (b2), plus bind helpers.
- `spike/dx11_textures.c` — the bake alpha corrected to `stp ? 128 : 255`
  (semi-transparency; opaque unchanged, so T1.3 verification still passes).
- `spike/dx11_shaders_test.cpp` — harness that draws a flat-textured, a
  gouraud-textured, a flat-untextured and a gouraud-untextured quad (checker
  SRV from `dx11_textures`, white substitute for untextured) plus a translucent
  flat quad blended with `BM_AVERAGE` over an opaque background, captures the
  backbuffer to BMP, and probes pixels to assert the shader modes and the blend.
- `premake5.lua` — new `dx11_shaders` project (compiles the renderer + textures
  + shaders modules + harness; links d3d11/dxgi/d3dcompiler/user32/gdi32).

## Verification

Built with `premake5 gmake2 --cc=gcc` + `mingw32-make dx11_shaders
config=release_x86` (32-bit, matching REDRIVER2.exe; needs the mingw32 runtime
DLLs beside it).

Run: `bin/Release/dx11_shaders.exe -res 800x600`. Writes relative to the exe:

- `dx11_shaders_frame.bmp/.txt` — backbuffer capture + pixel stats.
- `dx11_shaders_result.txt` — per-probe PASS/FAIL (
  flat_tex / goraud_tex / flat_untex / goraud_untex render, and the
  AVERAGE-blend center probe = 0.5 mix).

```

                          flat_tex   (175,475)=(248,248,248) PASS
```

All four shader modes render correctly (flat/gouraud x textured/untextured) and
the `BM_AVERAGE` centre probe equals exactly `0.5*red + 0.5*blue = (100,0,100)`,
matching the psyx blend table.

### Bugs found and fixed during verification

1. **`Dx11Renderer_CaptureToBMP` (T1.1) wrote the BMP with R and B swapped.**
   The capture loop read the R8G8B8A8 texel as `b = row[x*4+0]` (R) and
   `r8 = row[x*4+2]` (B), then wrote `out[0]=b; out[2]=r8` — putting R in the
   B slot and B in the R slot. The render itself was always correct; only the
   verification BMP was colour-swapped. Earlier harnesses escaped detection
   because they checked `brightPix`/`bbox` (order-independent) or symmetric
   colours. Fixed the channel order (`r8=row[0], bb=row[2]; out[0]=bb, out[2]=r8`).
   This is a shared-module fix that also corrects the T1.1/T1.2/T1.3 BMP
   captures (their stats were unaffected; T1.3's decode check uses `ReadBack`,
   not the BMP, so it was already correct).
2. **`Dx11Shaders_Create` had a `goto fail` crossing the `elems[]`
   initialization** (GCC error). Fixed by hoisting `elems[]` above the first
   `goto` (same pattern as T1.2).
3. **Harness probe variable named `rr` collided with the `Dx11RendererResult
   rr`** (compile error). Renamed the probe right-colour variables.
4. **First background probe point (25,25) landed inside the green quad C, not
   pure background.** Moved it to the middle band (200,300), left of the blend
   quad, where it is genuine background.
