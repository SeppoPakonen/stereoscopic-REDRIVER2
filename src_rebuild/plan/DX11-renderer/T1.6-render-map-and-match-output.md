# T1.6 — Model → arena adapter + headless harness

| **Phase**  | Phase 1 — Core DX11 renderer |

## Goal

Build the game-side bridge that turns a real `MODEL` mesh into the DX11
executor's input: world-space geometry pushed into the `dx11_resources` arena,
per-poly `texture_set/texture_id` resolved to a PSX tpage/clut and baked to an
SRV, flat/gouraud shading, world transform + bbox, and translucent sort keys —
verified headless with a dedicated harness.

## Scope (adjusted with the owner)

The original T1.6 ("render the map/terrain in-game and match `psyx` output")
requires the whole game to boot on DX11 (native window/swapchain wiring,
`DrawGame` branch, real MODEL + texture-table loading, A/B against the psyx GL
renderer) — a qualitative jump over T1.1–T1.5 that cannot be verified headless
in this environment. Per the owner's decision, T1.6 is scoped to the first
verifiable slice: a **game-agnostic MODEL→arena adapter module + headless
harness** (the same standalone-module pattern as T1.1–T1.5). The in-game
`DrawGame` rewiring, real texture-table loading and the psyx A/B comparison
move to a follow-up task (T1.7).

## Context

The executor (`spike/dx11_drawcmdexec`, T1.5) consumes vertex/index ranges that
are already in the T1.2 arena, plus a material (SRV handle), world transform,
flags and a local bbox. Nothing yet converts the game's `MODEL` mesh data into
that form. This task delivers that conversion as a standalone module so the
game's plot functions (T1.7) can call it with the mesh + a texture-resolve
hook.

### Game data this mirrors (from the T0.3 audit / T1.6 research)

- `MODEL` (`Game/engine/mdl.h`): `num_vertices`/`num_polys`, `SVECTOR` int16
  vertices, poly records with `u_char` vertex indices, `UV_INFO` tpage-local
  texel UVs, `texture_set`/`texture_id`, per-poly flat color or per-vertex
  (gouraud) color. Poly type stride via `PolySizes[56]` (`draw.c`).
- Texture resolve: `texture_pages[texture_set]` → tpage,
  `texture_cluts[texture_set][texture_id]` → clut (`Game/C/texture.c`).
- The adapter is game-agnostic: it consumes a **raw, uniform** poly/vertex
  description that mirrors the game's resolved data (the game shim computes
  lighting colors and supplies the texture-resolve hook). The variable-size
  poly-block walk itself stays in the game shim (T1.7); the adapter owns the
  real conversion: int16→float vertices, triangle split, **UV
  texel→normalized**, texture bake, flat/gouraud, world + bbox, translucent.

## Design

Raw input types (`spike/dx11_modeladapter.h`):

- `Dx11ModelVertex { short x,y,z; unsigned char r,g,b; }` — model-local vertex
  (mirrors `SVECTOR`); per-vertex rgb used for gouraud shading.
- `Dx11ModelPoly { u_char vi0..vi3; u_char u0,v0,u1,v1,u2,v2,u3,v3; u_char r,g,b;
  u_char shade; u_char blend; u_char twoSided; u_char nodepth; u_char
  texture_set; u_char texture_id; int sortKey; }` — one resolved poly
  (`vi3==vi2` for triangles); UVs are tpage-local texels.
- `Dx11ModelMesh { const Dx11ModelVertex *verts; int num_verts; const
  Dx11ModelPoly *polys; int num_polys; }`.
- `Dx11ModelTexture { u_short tpage, clut; int tex_x, tex_y, width, height; }` —
  the PSX region to bake (region **in texels**).
- `Dx11ModelTexResolve(void *user, u_char set, u_char id, Dx11ModelTexture *out)`
  → 0 on success. The game/harness supplies this; it maps `texture_set/id` to
  the tpage/clut + region and is responsible for having filled the VRAM staging
  (`Dx11Tex_CopyVRAM`).

Public entry: `int Dx11ModelAdapter_Submit(Dx11Res *res, Dx11Tex *tex,
Dx11DrawCmds *cmds, const Dx11ModelMesh *mesh, const float world[4][4],
void *texUser, Dx11ModelTexResolve texResolve, int *outPolys)`.

Per poly the adapter:
1. Resolves + bakes the texture (`Dx11Tex_Bake`) → SRV handle (white substitute
   when the resolve fails or the poly has no texture).
2. Converts the 3/4 referenced vertices to float (**world stays in the
   command CB**; the arena holds model-local float verts), with per-vertex rgb
   for gouraud or white for flat.
3. Pushes vertices (duplicated per poly, so same-material consecutive polys are
   **index-contiguous** → the T1.5 executor batches them) and 3/6 indices
   (tri `v0,v1,v2`; quad `v0,v1,v3` + `v0,v3,v2`).
4. **Normalizes UVs** by the baked region size: `u' = u / width`, `v' = v /
   height` (the game's UVs are tpage-local texels; the executor's shader samples
   normalized [0,1]).
5. Computes the poly's local bbox (for the executor's frustum cull).
6. Submits one `Dx11DrawCmdItem` (world, bbox, SRV, flatColor from the poly rgb
   when flat, shade/blend/twoSided/nodepth/translucent/sortKey).

## Verification

`premake5 gmake2 --cc=gcc` + `mingw32-make dx11_modeladapter config=release_x86`
(32-bit; mingw32 runtime DLLs beside the exe). Run
`bin/Release/dx11_modeladapter.exe -res 800x600`. Writes
`dx11_modeladapter_frame.bmp` + `dx11_modeladapter_result.txt` (probe results +
submitted/culled/drawCalls counts).

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_modeladapter_result.txt:  submitted=7 culled=1 drawCalls=5
                              CULL   off-screen poly removed (culled=1) PASS
                              BATCH  same-material pair -> 1 call (drawCalls=5) PASS
                              TEXTURE texA(400,199)=(248,0,0) red PASS
                              TEXTURE texB(601,300)=(248,0,0) red PASS
                              GOURAUD left(165,300)=(0,150,50) green PASS
                              GOURAUD right(249,300)=(0,24,175) blue PASS
                              WORLD  world(634,98)=(248,0,0) red PASS
                              SORT   center(400,300)=(112,100,100) expect teal-on-top PASS
                              TOTAL_FAILS=0 ADAPTER=PASS
```

The adapter converts the raw mesh into the arena + executor commands and the
scene renders correctly: the textured flat quads show the baked palette color
(red), the gouraud quad shows the green→blue per-vertex gradient, the
world-translated quad renders at its translated position (top-right), the two
same-texture contiguous quads batch into one `DrawIndexed` (5 calls for 7
commands), the off-screen poly is culled, and the two overlapping translucent
quads blend back-to-front — the nearer teal (`sortKey=5`) ends up on top of the
farther blue (`sortKey=10`) over the opaque red, giving the exact expected
`0.5*teal + 0.5*(0.5*blue + 0.5*red) = (112,100,100)`.

### Bugs found and fixed during verification

1. **Adapter: translucent flat alpha was always 1.0** — the flat/gouraud
   `flatColor[3]` (and gouraud vertex alpha) was hardcoded to 1, so translucent
   polys blended at 100% instead of the PSX semi-transparent 50% (`stp`). Fixed
   to `alpha = translucent ? 0.5f : 1.0f` for both the flat CB and the vertex
   color.
2. **Harness: 10× coordinate-scale mismatch** — the raw-model vertices are
   integer shorts converted verbatim to float, but the probe world-points used
   a 0.1 scale (e.g. `(1.2,0.6,-3)` vs vertices at `(-8,8,-30)`). The quads
   rendered correctly but at unexpected screen positions (the "world quad at the
   bottom" was actually a correctly-rendered quad whose world y was ~8..9,
   mostly clipped off the top). Fixed all probe points + the world translation
   to the same integer scale.
3. **Harness: quad vertex-index order** — the adapter (mirroring the game)
   splits quads as `(vi0,vi1,vi3)+(vi0,vi3,vi2)` with corner order
   `vi0,vi1,vi3,vi2 = TL,TR,BR,BL`. The harness fed the standard `TL,TR,BR,BL`
   as `vi0..vi3`, leaving a hole on the right of every quad. Swapped `vi2`/`vi3`
   in the raw polys to the game's convention.
4. **Harness: world quad back-facing** — its local vertices were arranged
   `BL,BR,TR,TL`, so both emitted triangles were back-facing and `CULL_BACK`
   dropped the whole quad. Reordered to `TL,TR,BR,BL`.
5. **Harness: SORT expectation** — the expected center colour assumed the opaque
   base was a blue flat quad, but texA is the **textured red** palette colour
   `(248,0,0)`, so the correct back-to-front blend is `(112,100,100)`, not
   `(50,100,150)`. The observed `(112,100,100)` (vs the wrong-order `(162,50,50)`)
   confirms the sort is correct; the probe now asserts teal-dominant.
