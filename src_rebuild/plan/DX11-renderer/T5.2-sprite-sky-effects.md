## Scope

The third feed slice of T5.2: rewire the **sprite / sky / effect** plot path to
submit world-space `DrawCommand`s under `-renderer dx11`, keeping the legacy GTE
+ `addPrim` path for `-renderer psyx`.

Following the T5.2 audit, the sprite/sky/effect contributors split into two
groups:

- **MODEL-based** (submitted) — reuse the existing `PlotFeed_SubmitModel` path:
  `DrawSprites` (tree billboards), `DrawThrownBombs`, `DrawSmashable_sprites`.
- **Sky** (`DrawSkyDome`/`PlotHorizonMDL`) — submitted via a **dedicated sky
  texture path**: the horizon MODEL's polys are textured per-poly from the game's
  `skytpage`/`skyclut` (VRAM) via `HorizonTextures[horizOffset + polyIndex]` with
  the `skytexuv` UV remap — NOT the model's `texture_pages`/`texture_cluts`.
- **addPrim single-primitives** (deferred) — no `MODEL` mesh; need a new
  single-primitive (`mesh == NULL` + `material`) renderer path:
  `DrawExplosion`, `DisplayDebris`/`DisplaySmoke`, `DrawRainDrops`,
  `DrawTyreTracks`, `addSubdivSpriteShadow`.

## Design

Same world-space convention as the terrain/tile + car feeds: `DrawCommand.world`
is **world space** (rotation + translation); the renderer builds its own
per-eye view.

### `DrawSprites` (tree billboards, draw.c)

- World rotation = **`face_camera_work`** (camera.h) — the billboard orientation
  in world space (identity or `RotMatrixY(-yaw)`). The legacy path pre-composites
  it as `face_camera = inv_camera_matrix * face_camera_work` for the GTE; the
  feed uses the world-space `face_camera_work` directly.
- World position = the sprite's **nearCell-resolved** position. Like tiles,
  `ppco->pos` is **packed relative to the cell origin**, so `DrawMapPSX` stores a
  resolved world position in a new `sprite_pos[]` array (parallel to `spriteList`)
  using the same `ci.nearCell + (short)(ppco->pos - nearCell)` resolve; `vy =
  (short)ppco->pos.vy >> 1`.
- Submit: `PlotFeed_SubmitModel(model, &face_camera_work, &sprite_pos[i], z,
  PLOT_TRANSPARENT)` (tree billboards are semi-transparent).

### `DrawThrownBombs` (bomberman.c)

- World rotation = `object_matrix` (InitMatrix + RotMatrixY/Z), world position =
  `bomb->position` (already world after the GTE restore). Submit:
  `PlotFeed_SubmitModel(gBombModel, &object_matrix, &bomb->position, z, 0)`.

### `DrawSmashable_sprites` (debris.c)

- World rotation = `object_matrix` (RotMatrixY/Z, or InitMatrix when the sprite
  shape flag is set), world position = `dam->pos`. Submit:
  `PlotFeed_SubmitModel(model, &object_matrix, &pos, z, 0)`.

Camera-depth `z` for the sort key is computed the same way as `RenderModel`
(`dot inv_camera_matrix row 2 · (worldpos − camera_position)`).

## Integration points

1. `draw.h`/`draw.c`: `VECTOR sprite_pos[MAX_DRAWN_SPRITES]` (declared/defined);
   `DrawMapPSX` fills it in the sprite-collection branch (nearCell-resolved).
2. `DrawSprites` (draw.c): dx11 branch submits each billboard MODEL (world =
   `face_camera_work` + `sprite_pos[i]`, `PLOT_TRANSPARENT`).
3. `DrawThrownBombs` (bomberman.c): dx11 branch submits the bomb MODEL.
4. `DrawSmashable_sprites` (debris.c): dx11 branch submits the smashable MODEL.
5. Includes: `bomberman.c`/`debris.c` gained `../render/renderer.h`.

### Sky (`DrawSkyDome`/`PlotHorizonMDL`, sky.c)

- The sky horizon MODEL's polys are **textured per-poly from the game's sky
  tables** — `skytexnum = HorizonTextures[horizOffset + polyIndex]` →
  `skytpage[skytexnum]`/`skyclut[skytexnum]` (VRAM) + `skytexuv[skytexnum]`
  UVs (remapped `u2,u3,u0,u1`, matching `PlotSkyPoly`) — NOT the MODEL's
  `texture_set`/`texture_id`.
- **`DrawCommand.skyModel`** + **`horizOffset`** (drawcmd.h) mark a command as a
  sky horizon model. `PlotFeed_SubmitSkyModel` (sky.c) builds it: camera-anchored
  (world pos = `camera_position + (0, sky_y_offset[GameLevel], 0)`, identity
  rotation), `DRAWCMD_OPAQUE`.
- **`Dx11SkyTextures`** (dx11_gamefeed.h) bundles the game's
  `skytpage`/`skyclut`/`skytexuv`/`HorizonTextures`; `main.c`
  `Dx11Game_RenderFrame` passes `&skyTex` to `Dx11GameFeed_RenderFrame`.
- **`Dx11GameFeed_SkyModelToMesh`** (dx11_gamefeed.c) converts the horizon MODEL
  to the adapter mesh, setting each poly's `carTpage`/`carClut` (the direct-bake
  car path) to the sky page/clut + the remapped `skytexuv` UVs (page-X scaled by
  pageW). `RenderFrame` dispatches on `dc->skyModel`.

## Deferred (documented here)

- **addPrim effects** (explosions, debris, smoke, rain, tyre tracks, sprite
  shadows): need a new single-primitive (`mesh == NULL` + `material`) renderer
  path (a billboard quad from world pos + size + material, plus executor
  `MATBLEND_*` blend-state binding).

## Non-breaking parallel submit

Under dx11 the sprite/effect paths append commands and keep the GTE draw running
in parallel (the SDL legacy window still shows the full scene; the DX11 companion
window renders the feed).
