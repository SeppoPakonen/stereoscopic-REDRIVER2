# T1.5 — Draw-command execution (culling, sort, batch)

|            | |
------------|-|
| **Phase**  | Phase 1 — Core DX11 renderer |
| **Milestone** | M1 — Core DX11 renderer |
| **Status** | planned |

## Goal

Implement the draw-command executor: projection, frustum culling, sorting
(opaque front-to-back / transparent back-to-front) and batching by material, so
the renderer owns rendering as the architecture requires.

## Context

The game submits a draw-command list (T0.2); the renderer owns the rest. Per the
architecture, the game keeps coarse PVS/cell culling, but frustum culling,
depth sorting and material batching move into the renderer. This replaces the
OT depth-sort (`Z >> 1`) with a proper sort + state batching pass.

## Steps

- [ ] Build the per-eye view/projection CB (T0.4/T1.2) and transform each draw
      command's bbox/geometry for frustum culling.
- [ ] Sort commands: opaque by material (front-to-back), transparent by depth
      (back-to-front), using the sort key from `DrawCommand`.
- [ ] Batch consecutive matching-material/state commands into single draw calls.
- [ ] Emit final `DrawIndexed` calls with the correct VB/IB/CB/PS state.
- [ ] Handle the render-only logic that stayed in the game (LOD, animation)
      cleanly at the command source.

## Acceptance criteria

- [ ] The executor renders the draw-command list with correct depth and order.
- [ ] Frustum culling removes off-screen commands (matches `psyx` culling).
- [ ] Batching reduces API calls without changing output.
