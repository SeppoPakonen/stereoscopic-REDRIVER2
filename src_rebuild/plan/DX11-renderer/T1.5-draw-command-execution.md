# T1.5 — Draw-command execution (culling, sort, batch)

|            | |
|------------|-|
| **Phase**  | Phase 1 — Core DX11 renderer |
| **Milestone** | M1 — Core DX11 renderer |
| **Status** | done |

## Goal

Implement the draw-command executor: projection, frustum culling, sorting
(opaque front-to-back / transparent back-to-front) and batching by material, so
the renderer owns rendering as the architecture requires.

## Context

The game submits a per-frame draw-command list (T0.2); the renderer owns the
rest. Per the agreed ownership split, the game keeps coarse PVS/cell culling,
animation and LOD; frustum culling, depth sorting and material batching move
into the renderer. This replaces the OT depth-sort (`Z >> 1`) with a proper
sort + state-batching pass.

## Scope note: standalone executor module + harness (like T1.1–T1.4)

The executor is `spike/dx11_drawcmdexec.{h,c}` — a **game-agnostic** module
that consumes a per-frame list of executor commands (geometry already gathered
into the T1.2 arena as vertex/index ranges + a material + world transform +
sort key + flags + a local-space bbox). It owns projection, frustum culling,
sorting, batching and the final `DrawIndexed` emission on top of
`dx11_resources` (arena/VB/CB), `dx11_textures` (SRVs) and `dx11_shaders`
(PSX render states). The harness drives it headless.

The **game-side adapter** that walks a `DrawCommand`/`MODEL` mesh, resolves
`texture_set/texture_id` → tpage/clut → `Dx11Tex_Bake`, world-transforms the
`SVECTOR` vertices and pushes them + the executor command into the arena is
**T1.6** (render map/terrain + match output). The executor here is the
renderer-side logic that T1.6 feeds.

## Design

- **Per-eye view/proj CB** (`Dx11Res_SetViewProj`, T1.2) is set once per frame
  by the caller; the executor builds the world CB per command via
  `Dx11Res_AllocCB`/`SetCB` and binds it with `BindWorldSlot`.
- **Frustum culling**: the caller supplies a local-space bbox per command; the
  executor transforms its 8 corners by `world · viewProj` and culls the command
  if all 8 corners lie outside any clip plane (`x<−w, x>w, y<−w, y>w, z<0, z>w`).
- **Sorting**:
  - *Opaque* commands sort by material/state key (texture + blend + shade +
    two-sided + no-depth), then front-to-back by `sortKey`.
  - *Translucent* commands sort **back-to-front** by `sortKey` (largest = far =
    drawn first, matching the PSX OT order), independent of material.
  - Opaque commands draw before translucent commands.
- **Batching**: consecutive commands that share material/state **and** the same
  world transform **and** are index-contiguous in the arena merge into a single
  `DrawIndexed` (no output change, fewer API calls). This is the natural case
  when a mesh's same-material polys are pushed sequentially.
- **Emit**: one world-CB slot per command, `BindGeometry` + `BindWorldSlot` +
  `Dx11Shaders_Bind`(flat/gouraud) + `SetBlend`/`SetDepthOpaque`/`SetRaster` +
  texture SRV (or the white substitute when `texture == -1`), then
  `DrawIndexed`.

## Verification

Built with `premake5 gmake2 --cc=gcc` + `mingw32-make dx11_drawcmdexec
config=release_x86` (32-bit; needs the mingw32 runtime DLLs beside it).

Run: `bin/Release/dx11_drawcmdexec.exe -res 800x600`. Writes:
- `dx11_drawcmdexec_frame.bmp/.txt` — backbuffer capture + stats.
- `dx11_drawcmdexec_result.txt` — PASS/FAIL probes (cull removed the off-screen
  command; the translucent overlap shows the nearer command on top; the
  same-material pair drew as one call) + `drawCalls` / `culled` counts.

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_drawcmdexec_result.txt:  submitted=6 culled=1 drawCalls=4
                              CULL off-screen command removed (culled=1) PASS
                              BATCH same-material pair -> 1 call (drawCalls=4) PASS
                              SORT  center(400,300)=(50,100,150) expect(50,100,150) PASS
                              EMIT  main(350,210)=(0,0,200) blue PASS
                              EMIT  batchA(220,300)=(0,200,0) green PASS
                              EMIT  batchB(270,300)=(0,200,0) green PASS
                              TOTAL_FAILS=0 EXEC=PASS
dx11_drawcmdexec_frame.txt:   brightPix=64896 bbox=(192,196)-(503,403) Rrange[0,50]  (800x600)
```

The executor frustum-culls the off-screen command, batches the two
same-material/index-contiguous quads into one `DrawIndexed` (4 calls for 6
commands), draws opaque before translucent, sorts the two overlapping
translucent quads **back-to-front** (the nearer teal `sortKey=5` ends up on top
of the farther red `sortKey=10` over the opaque blue), and the in-view opaque
quads render at their expected positions. The centre blend `(50,100,150)` is
exactly `0.5*red → 0.5*teal → blue` back-to-front.

### Bugs found and fixed during verification

1. **`Dx11DrawCmds_Submit` never incremented `c->count`** (copy without
   `++count`) → `submitted=0`, nothing drew. Fixed.
2. **Frustum cull used the wrong matrix access** — it transformed corners with
   the non-transposed `out[j]=Σ p[i]·M[i][j]`, but the shader's `mul` reads the
   matrix transposed (`out[j]=Σ p[i]·M[j][i]`), so the cull computed a negative
   `w` and culled **everything**. Fixed `XformPoint` to replicate the shader
   (`M[j][i]`); the cull now matches what the VS actually rasterizes.
3. **The executor never bound a sampler** — the PS `Sample` had no sampler
   bound, so textured output was undefined → nothing rendered. Fixed by binding
   `Dx11Res_GetSampler` when starting each batch.
4. **Harness called `Dx11Res_BeginFrame` after `SetViewProj`** — `BeginFrame`
   resets `vpSet=0`, so the view/proj CB was never uploaded (identity →
   geometry clipped at far plane). Fixed the call order.
5. **Harness `AddQuad` referenced an uninitialised `vi[0]`** — the first vertex
   index of each triangle was garbage, so a quad rendered as a wrong triangle
   (and the translucent quads didn't appear). Fixed to use the actual
   `PushVertex` return for vertex 0.
