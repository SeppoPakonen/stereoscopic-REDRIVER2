## Scope

The **consumer half** of the in-game path: wire `DrawGame`'s `-renderer dx11`
branch to consume the draw-command arena (produced by the T5.2 terrain/tile
core) and render it through the full DX11 pipeline
(`Dx11GameFeed_RenderFrame` → per-eye → composite) to a **companion DX11
window**, in **parallel** with the legacy SDL/PsyX path (A/B display, per the
owner's choice). The SDL window keeps showing the full legacy scene; the DX11
window shows the real terrain/tile arena render for visual comparison.

This is the first concrete "move everything to DX11" step: the dx11 backend now
owns a real render window driven by the game's actual `DrawCommand` feed.

## Design

### Display target (approved: A/B parallel)

`Dx11Renderer`/`Dx11GameFeed` create their own native Win32 window (T1.1
contract). The game's display is SDL/PsyX (GL). Rather than mix a D3D11
swapchain onto the SDL window's HWND (risky: GL context + D3D11 swapchain on the
same HWND), the dx11 consumer renders to a **companion DX11 window** in parallel
with the legacy SDL window. The two windows are independent A/B outputs.

### main.c consumer (static, `_WIN32`-guarded)

- `Dx11GameDisplay` — lazily-created, cached `Dx11Renderer` (640x480 window,
  internal 320x240) + `Dx11Res`/`Dx11Tex`/`Dx11Shaders`/`Dx11DrawCmds`/
  `Dx11Composite`. Created once on the first frame with a non-empty arena
  (`tried`/`ok` guards; a failed create is not retried). Reused every frame
  (the T4.3 mono-path gotcha: don't create a fresh renderer per frame).
- `Dx11Game_RenderFrame()` — reads the arena (`DrawCmd_Count`/`DrawCmd_Data`),
  converts the camera (`camera_position` → camPos, `camera_angle.vy` · 2π/4096
  → yawRad), builds the projection from the game's `FrAng` (horizontal half-FOV,
  game angle units → vertical FOV via the 320x240 aspect), and calls
  `Dx11GameFeed_RenderFrame` with `DX11C_MODE_MONO`, an **untextured** resolve,
  `cmdColors=NULL` (white), `sep=0`, `bmpOut=NULL`.
- Called at the end of `DrawGame` under `Renderer_IsDX11()` (before the legacy
  `PsyX_EndScene`), independent of the legacy present.

### Supporting changes

- `premake5.lua` — added `spike/dx11_gamefeed.{h,c}` to the REDRIVER2 build.
- `dx11_gamefeed.c/.h` — portable includes (`"engine/mdl.h"`,
  `"render/drawcmd.h"`); `CaptureToBMP` now guarded with `if (bmpOut)` so the
  in-game consumer passes NULL (no per-frame BMP).
- `drawcmd.{h,c}` — added `DrawCmd_Data()` (contiguous arena array accessor for
  the renderer pass).

### Camera/projection caveats (need in-game tuning)

- The DX11 camera is **yaw-only** (`Dx11Stereo_ViewMatrix`); the game's camera
  pitch/roll are ignored. The yaw sign/handedness may need flipping for exact
  alignment — unverifiable headless.
- Projection near=1, far=200000 (the game's large world units); depth precision
  at the huge far is coarse but renders.
- **Textures**: the terrain feed now bakes real tpage/clut regions from VRAM
  (see `T5.2-feed-texture-baking.md`).
