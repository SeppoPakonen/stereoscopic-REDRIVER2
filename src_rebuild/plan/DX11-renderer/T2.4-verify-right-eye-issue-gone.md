# T2.4 — Verify right-eye map issue is gone

|            | |
------------|-|
| **Phase**  | Phase 2 — Stereo natively |
| **Milestone** | M2 — Stereo natively |
| **Status** | done |

## Goal

Confirm, in the DX11 backend, that the legacy "right-eye map/terrain
disappears" bug is gone — proving it was downstream in the GL offscreen
rasterization/composite and not a scene/camera/culling problem.

## Scope (adjusted with the owner)

The as-written T2.4 ("run the headless iteration harness `-stereo 3 -iterlog`
on a mission where the right-eye map used to disappear") requires the running
game. Per the owner's decision (same as T1.6–T2.3), T2.4 is scoped to the
verifiable slice that proves the bug is structurally absent: a **standalone
stereo-scene harness** that renders a multi-object scene (map/terrain + car)
into both eye RTs via the per-eye view matrices (T2.2), and verifies the
right-eye RT contains the full scene with equal draw counts and a lateral-offset
symmetric output. The in-game mission run (the real `-renderer dx11` wiring)
stays a later integration task.

## Context

The bug was tracked to the GL offscreen path (`DrawOTag`/composite for the
second eye's texture), not to queueing/culling/camera. The DX11 path renders
each eye directly into its own RT (T2.1), so the shared-offscreen-target
failure mode cannot occur. This task exercises that path with a representative
scene and captures the evidence.

## Design

`spike/dx11_stereoscene_test.cpp` (game-agnostic, on the full DX11 stack +
`dx11_stereo`):

- a scene of two opaque objects — a large green **map/terrain** quad (full
  view at z=-3) and a smaller red **car** quad (off-center, z=-2.8);
- for each eye, builds the per-eye view from `Dx11Stereo_ViewMatrix` (sep=0.1)
  and sets `viewProj = view * proj` (row-vector, column-major), renders the
  scene into that eye's offscreen RT (T2.1), records
  `Dx11DrawCmds_SubmittedCount`, and captures the RT to a BMP;
- probes:
  - `MAP_L` / `MAP_R` — a map-only pixel is green in **both** eyes (the right
    eye's map is present — the legacy symptom);
  - `CAR_L` / `CAR_R` — the car pixel is red in both eyes;
  - `DUAL_DRAWCOUNT` — both eyes submitted the same number of commands;
  - `SYMMETRIC` — both eyes contain the full scene (map + car present), i.e.
    the eyes differ only by the lateral offset, not by absent content.

## Verification

`premake5 gmake2 --cc=gcc` + `mingw32-make dx11_stereoscene config=release_x86`
(32-bit; mingw32 runtime DLLs beside the exe). Run `bin/Release/dx11_stereoscene.exe`.
Writes `dx11_stereoscene_result.txt` (map / car / drawcount / symmetric probes).

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_stereoscene_result.txt:
   MAP_L left map-pixel(229,120)=(0,200,0) green PASS
   MAP_R right map-pixel(229,120)=(0,200,0) green PASS
   CAR_L left car-pixel(90,120)=(220,0,0) red PASS
   CAR_R right car-pixel(90,120)=(220,0,0) red PASS
   DUAL_DRAWCOUNT left=2 right=2 equal PASS
   SYMMETRIC map present in both eyes PASS
   TOTAL_FAILS=0 RIGHTEYE=PASS
```

Both eyes render the full scene. The right-eye RT contains the map/terrain at
the same map pixel as the left (green, not background) — the legacy "right-eye
map disappears" symptom is absent. Draw counts are equal (2 == 2) and both eyes
carry the same objects; the eyes differ only by the small lateral offset from
`Dx11Stereo_ViewMatrix` (sep=0.1). This is the structural proof: in DX11 each
eye renders into its own independent RT (T2.1), so the GL shared-offscreen /
`GR_ResetOffscreenSize` failure mode cannot occur.

### Bugs found and fixed during verification

One real integration bug, caught by this harness and fixed in `dx11_stereo`
(T2.2): `Dx11Stereo_ViewMatrix` returned the **standard column-vector view
matrix V** (rows = right/up/-forward, translation in the last column), but the
DX11 pipeline convention (C++ row-major storage, HLSL `mul` reads the matrix
transposed → effective = `mat*p`, projection stored as `P^t`) needs the view in
the **transposed form `V^t`** so that `viewProj = view * proj` composes to
`(P*V)^t`. With `V` (not `V^t`), the eye offset folded into the projection's
w-axis and the lateral parallax rendered ~3x too large and asymmetric — the
left eye's car landed at col 136 instead of the correct 116. The pure-math T2.2
test could not catch this (it never rendered). Fixed `ViewMatrix` to output
`V^t` (basis in columns, translation in the last row), updated the T2.2 STABLE
probes to check the last-row translation, and re-verified both `dx11_stereo`
(`STEREO=PASS`) and this harness (`RIGHTEYE=PASS`). The right-eye-map symptom
itself is structurally absent — each eye renders into its own independent RT
(T2.1), so the GL shared-offscreen / `GR_ResetOffscreenSize` failure mode cannot
occur.
