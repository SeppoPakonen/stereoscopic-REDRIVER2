# T2.4 — Verify right-eye map issue is gone

|            | |
------------|-|
| **Phase**  | Phase 2 — Stereo natively |
| **Milestone** | M2 — Stereo natively |
| **Status** | planned |

## Goal

Confirm, in the DX11 backend, that the legacy "right-eye map/terrain
disappears" bug is gone — proving it was downstream in the GL offscreen
rasterization/composite and not a scene/camera/culling problem.

## Context

The bug was tracked to the GL offscreen path (`DrawOTag`/composite for the
second eye's texture), not to queueing/culling/camera. DX11 renders each eye
directly into its own RT (T2.1), so it should be inherently absent. This task
verifies that and captures the evidence.

## Steps

- [ ] Run the headless iteration harness (`-stereo 3 -iterlog`) on a mission
      where the right-eye map used to disappear.
- [ ] Confirm both eyes' draw counts are equal and the right-eye RT contains the
      full map/terrain.
- [ ] Capture + compare left/right eye screenshots; confirm both are complete.
- [ ] If map still missing in DX11, root-cause (it would now be a DX11-side
      issue, not the legacy GL one).

## Acceptance criteria

- [ ] Right-eye map/terrain renders fully in DX11 stereo.
- [ ] Left/right eye outputs are symmetric apart from the lateral offset.
- [ ] The legacy bug is documented as resolved in the DX11 path.
