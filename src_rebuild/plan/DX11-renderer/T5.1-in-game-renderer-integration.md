## Goal

Build the **game-facing renderer integration** — the function `DrawGame`'s
`-renderer dx11` branch will call each frame — that consumes the game's real
**`DrawCommand` list** (`drawcmd.h`) and drives the full DX11 pipeline:
**draw-command → per-eye → composite** (MODEL mesh → `Dx11ModelAdapter` → arena →
executor → per-eye view → composite). This is the renderer half of the
"DrawGame → draw-command → per-eye → composite" path.

## Scope (adjusted with the owner)

The full in-game rewiring has two halves: **(A) the renderer** (consume the
draw-command list and render it through per-eye → composite) and **(B) the feed**
(rewrite the ~40 plot functions to emit draw commands). Per the owner's decision,
this task delivers the **renderer half** (A), verified headless with a synthetic
`DrawCommand` scene (the game does not reach `DrawGame` headless, so the plot
functions' feed rewiring (B) is a follow-up that needs a running game).

## Context

The draw-command feed contract (`drawcmd.h`) and its arena (`drawcmd.c`) exist but
no plot function submits yet. The DX11 stack (per-eye RTs T2.1, per-eye view T2.2,
composite T2.3, model adapter T1.6) is complete and headless-verified standalone.
This task wires them together on the game side: a module that takes a
`DrawCommand[]` and renders it, exactly as `DrawGame` will call it.

## Design

- **`spike/dx11_gamefeed.{h,c}`** — a game-aware renderer integration module:
  - `Dx11GameFeed_ModelToAdapter(model, flatColor, outMesh)` — converts a `MODEL`'s
    flat-textured-quad polys (`PL_POLYFT4`, poly type `id & 31` ∈ {11,21,23}, stride
    `PolySizes[type]`; the dominant terrain/tile/car case) into the `Dx11ModelMesh`
    raw format (int16 vertices → `Dx11ModelVertex`, per-poly
    `vi0..vi3`/`uv0..uv3`/`texture_set`/`texture_id`, flat color). Full shade/LOD/
    gouraud + all poly types are a follow-up.
  - `Dx11GameFeed_RenderFrame(ren, res, tex, sh, cmds, drawCmds, numCmds, camPos,
    sep, swap, mode, outBmp)` — for each `DrawCommand` (mesh != NULL): convert via
    `ModelToAdapter` + `Dx11ModelAdapter_Submit` (with a texture-resolve hook that
    fills a baked VRAM region), then render per-eye (`Dx11Stereo_ViewMatrix`) into
    the two eye RTs and composite SBS/TB/MONO into the backbuffer, captured to BMP.
- **`spike/dx11_gamefeed_test.cpp`** — harness: builds a synthetic map (large green
  textured quad) + car (small red quad) as real `MODEL`/`DrawCommand` objects and
  renders them through the integration, verifying: `MAP_L`/`MAP_R` (the map is
  present in both eye RTs), `CAR_L`/`CAR_R`, `MONO` (map fills the frame — the base
  scene), and `COMPOSITE` (SBS left=eye0/right=eye1). This drives the actual
  `DrawCommand` → `Dx11ModelAdapter` → per-eye → composite path.
- **premake project `dx11_gamefeed`** — `dx11_gamefeed.{h,c}` +
  `dx11_gamefeed_test.cpp` + the core DX11 modules (renderer/resources/textures/
  shaders/drawcmdexec/modeladapter/stereo/composite) + `Game/render/drawcmd.c` +
  `Game/engine/mdl.h` types; links `d3d11`/`dxgi`/`d3dcompiler`/`user32`/`gdi32`.

### Bugs found and fixed during verification

- **Synthetic-model quad winding (v2/v3) was inverted**, producing bow-tie
  triangles: the adapter expects `vi0,vi1,vi3,vi2 = TL,TR,BR,BL` (the game's
  winding, where the renderer reads `v0,v1,v3` as the triangle and `v2` as the
  4th corner), but the harness's `MakeQuadModel` set `v2=BR, v3=BL`. The two
  emitted triangles then crossed (both on the left, leaving the right half of
  every quad empty → a "chevron"/"V-notch" shape). Fixed `MakeQuadModel` to the
  game convention (`v2=BL, v3=BR`). The untextured scene (UVs all 0) masked the
  UV part of the bug, so only the geometry bow-tie surfaced.
