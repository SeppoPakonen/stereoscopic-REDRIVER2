## Goal

Prove that each stereo eye renders into its **own** DX11 render target at the
configured internal resolution (no 320x240 lock), replacing the fragile
shared-GL offscreen path — verified headless with a dedicated harness.

## Scope (adjusted with the owner)

The per-eye RT infrastructure already exists: `Dx11Renderer` (T1.1) allocates
**two** offscreen render targets (`DX11R_OFFSCREEN_COUNT = 2`) at the internal
resolution, with `BindOffscreen(index)`, `GetOffscreenRTV/SRV/Texture` and an
internal-resolution viewport (`offVp`). The legacy GL path that had to work
around the shared `g_offscreenRTTexture/2` + `GR_ResetOffscreenSize` resize bug
is simply not used here. So T2.1 is a **verification harness** (the same
standalone-module + harness pattern as T1.1–T1.8): it renders a distinct
coloured quad into each eye's RT and asserts the two RTs are independent and
per-eye, at a configurable internal resolution, while the non-stereo path still
renders to the backbuffer.

## Design

`spike/dx11_eyetargets_test.cpp` (reuses the T1.5 executor scaffold):

- Creates the full stack (renderer + resources + textures + shaders +
  executor) at a configurable internal resolution (`-ires`, default 320x240).
- For **eye 0** (left): clear offscreen RT 0 to a dark base, then
  `BindOffscreen(0)` + submit + execute a full-eye **red** quad; capture the
  offscreen texture to `eyetargets_left.bmp`.
- For **eye 1** (right): same with a **blue** quad → `eyetargets_right.bmp`.
- **Non-stereo**: `BindBackbuffer` + a **green** quad → `eyetargets_back.bmp`.
- Probes:
  - `EYE0` — left BMP centre is red (its own RT, not the backbuffer).
  - `EYE1` — right BMP centre is blue (independent of eye 0).
  - `INDEP` — left BMP pixel ≠ right BMP pixel at the same position (no
    cross-eye reuse).
  - `IRES` — the captured BMP dimensions equal the configured internal
    resolution (configurable, not 320x240-locked).
  - `BACK` — the backbuffer capture is green (non-stereo path unaffected).

## Verification

`premake5 gmake2 --cc=gcc` + `mingw32-make dx11_eyetargets config=release_x86`
(32-bit; mingw32 runtime DLLs beside the exe). Run
`bin/Release/dx11_eyetargets.exe -res 800x600 -ires 320x240`. Writes
`eyetargets_*.bmp` + `dx11_eyetargets_result.txt` (per-eye/independence/
internal-res/backbuffer probes).

### Actual observed output (mingw32 32-bit, release_x86)

```
dx11_eyetargets_result.txt (ires 320x240):
   EYE0 left(160,120)=(220,0,0) red PASS
   IRES left bmp 320x240 expect 320x240 PASS
   EYE1 right(160,120)=(0,0,220) blue PASS
   INDEP left(220,0,0) vs right(0,0,220) differ PASS
   BACK backbuffer(400,300)=(0,220,0) green PASS
   TOTAL_FAILS=0 EYETARGETS=PASS

(also PASS at -ires 480x360: IRES left bmp 480x360 expect 480x360 PASS)
```

Each eye renders into its **own** offscreen RT at the configured internal
resolution: the left RT holds a red quad, the right RT a blue quad (identical
positions, independent contents — no cross-eye reuse), the captured dims equal
the configured internal resolution (configurable, not 320x240-locked), and the
non-stereo backbuffer path renders separately (green). The `GR_ResetOffscreenSize`
workaround from the shared-GL path is not needed: the per-eye RTs simply hold
their own contents across the two binds.

### Bugs found and fixed during verification

No bugs — the per-eye RT pair (`DX11R_OFFSCREEN_COUNT = 2`, `BindOffscreen` with
an internal-resolution viewport) from T1.1 already works as intended. Only a
harness-level detail: each offscreen RT is cleared with
`ClearRenderTargetView` (since `BeginFrame` clears only the backbuffer) before
the eye quad is drawn.
